# 术语速查与动手学习路线

类型：查阅表与学习练习。无需一次记住所有缩写，遇到时查本页即可。

## 1. 硬件与设备软件

| 术语 | 通俗解释 |
| --- | --- |
| IoT | 物联网，让设备交换信息并与真实世界互动 |
| MCU | 集成处理器、存储和外设的小型控制芯片 |
| CPU / GPU | 处理与计算资源；GPU适合部分并行计算，具体模型是否需要它取决于工作负载 |
| RAM | 程序运行时使用的内存，断电后通常不保留内容 |
| Flash | 保存固件、配置或内容的非易失存储；并非所有空间都能任意分配 |
| 固件 | 设备上运行的软件 |
| SDK / ESP-IDF | 开发工具与库；ESP-IDF是ESP32系列采用的开发框架 |
| I2S | 数字音频接口，常用于连接麦克风或音频输出器件 |
| BOM | 物料清单，记录组成产品的器件、数量、规格与成本条件 |
| OTA | 通过网络交付更新；可靠升级还包括校验、兼容与恢复 |

## 2. 网络与业务语义

| 术语 | 通俗解释 |
| --- | --- |
| 局域网 / 互联网 | 家中或局部网络 / 连接远端服务的网络 |
| BLE | 低功耗蓝牙，需进一步区分实际角色与使用方式 |
| 网关 / Broker | 设备接入与管理角色 / MQTT消息分发服务器，可能部署在同一主机 |
| MQTT / Topic | 发布订阅消息协议 / 消息分发主题 |
| HTTP / WebSocket | 常用应用通信方式，分别用于请求响应及持续双向交换等场景 |
| API / CLI | 程序调用入口 / 命令行操作入口 |
| 物模型 | 描述设备属性、动作和事件的约定 |
| 属性 / 事件 / 命令 | 可读取的状态 / 已发生的信息 / 请求执行的操作 |
| 回执 / 观测 | 对操作处理结果的反馈 / 对状态或物理现象的读取 |
| 幂等 / 原操作 | 重复请求按合同关联同一次操作 / 可查询的原始业务操作 |
| 会话 / 会话代次 | 一段有身份和上下文的交互 / 用来区分新旧交互结果的版本边界 |

## 3. AI 与时延

| 术语 | 通俗解释 |
| --- | --- |
| ASR | 语音识别，把声音转为文字 |
| LLM | 语言模型，根据输入和上下文生成文字或结构化结果 |
| TTS | 语音合成，把文字变为声音 |
| Agent | 在有边界的任务中使用模型与工具的应用程序 |
| 流式 | 输入或输出按片段传递，先准备好的部分先交给后续处理 |
| VAD / 话语结束判断 | 检测是否有人声 / 判断这一轮是否已经说完；两者都不等于理解语义 |
| 回声处理 | 减少喇叭播音对麦克风输入的干扰，是边听边说需要处理的问题之一 |
| 首段时延 | 从明确起点到第一段有效输出的时间；文字首段和可听语音首段要分别定义 |
| p50 / p95 | 50% / 95%的样本达到的指标值，统计时需要同时说明失败与测量条件 |
| 降级 | 部分依赖不可用时，按产品配置保留可用功能并解释限制 |

## 5. 不买硬件也可以开始的练习

项目已有按钮与灯光模拟器。先阅读[本地开发说明](../../../deploy/dev/README.md)，按其当前环境要求准备工具，再使用其中已有的启动与操作入口。本教程不维护第二份安装命令和工具版本。

在模拟环境中观察：按钮事件在哪里产生、规则在哪里判断、设备命令怎样关联原操作、反馈怎样更新界面。模拟通过只能说明对应的软件行为，真实供电、无线、麦克风和灯光效果还要实机验证。

## 6. 三道检查理解的问题

**问题一：家里断互联网，局域网还在，按钮联动灯是否还能工作？** 若对应规则与设备接入都在本地、已正确实现和部署，就具备继续工作的条件；要通过断公网实验确认。

**问题二：AI 返回“让小车前进”，下一步是什么？** 应用与网关核对当前权限、能力和参数，由设备执行受限动作；低层控制和保护继续在设备本地。

**问题三：在小米官网看到一个商品名称，怎样变成可靠资料？** 先确认准确型号，再读相关参数或说明书，记录来源与版本，分开原文明示、自己的理解和未确认项；实际支持另做验证。
