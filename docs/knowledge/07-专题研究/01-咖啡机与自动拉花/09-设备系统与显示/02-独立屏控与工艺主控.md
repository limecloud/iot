# 独立屏控与工艺主控

将界面处理器与工艺 MCU 分开，可以分别配置算力、维护软件和安排开发责任。屏控可以采用适配过的 openvela 图形系统，也可以采购带运行环境的 HMI 模组；两者都需要核实供应商能力。以下属于参考架构，没有选定模组或验证设备。

## 硬件与职责

界面侧负责触摸、中文输入、模板预览、任务列表和顾客提示。工艺侧负责传感、加热、泵阀、打印运动、互锁和执行记录。两侧通过经评估的 UART、CAN、SPI 或其他链路交换业务请求和状态；通信物理层本身不保证任务语义可靠。

两个处理器可以位于同一块 PCB，也可以做成主控板与显示板。是否独立画屏控板、复用厂商模组或委托设计，取决于装配、供应链、维修和接口约束。采用“智能屏”不意味着免除整机主控与结构设计。

## 双侧协议与故障边界

| 责任 | 设计和验证要求 |
| --- | --- |
| 指令边界 | 传递受限配方、图像任务或参数；本地工艺主控校验范围、状态与执行条件 |
| 任务语义 | 定义任务标识、版本、校验、接收与完成状态，处理重复、错序、超时和取消 |
| 状态展示 | 工艺侧为真实执行状态的来源；屏幕不能用动画结束推断制作成功 |
| 断线与重启 | 定义屏控重启、链路失联时工艺是否继续、受控停止或拒绝新任务；按工艺风险验证，不能统一假设继续或立即断电 |
| 结果不确定 | 执行后回执丢失时核对持久化记录与现场，防止自动重做一杯或重复打印 |
| 版本维护 | 协议、字体资源、屏控固件与工艺固件建立兼容矩阵，验证升级中间状态及回退 |

屏控分离可降低界面负载直接占用工艺主控资源的影响，但电源、通信和系统设计仍可能形成共同故障点，不能据此宣称完成安全隔离。

## 采购与量产验收

采购 HMI 时形成分辨率、字体/输入法、外部图片下发、可用接口、资源工具许可、固件维护、物料变更和持续供货清单。演示中的拼音键盘不代表覆盖目标顾客姓名；供应商自带界面也不代表开放第三方图像打印接口。

验证两侧并发负载、断连、重启、错误报文、重复任务和升级兼容；对触摸湿手误操作、蒸汽凝露、安装与清洁条件进行整机测试。按工艺定义失效行为和交付责任。
