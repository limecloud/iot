# 功能分支 D：自动倒奶模块与机器人

这个分支针对真实倒奶形成图案。它可以作为独立模块，也可以与整机共同开发；选择成熟整机、自研主控或整机研发之后，仍需单独验证这一功能。

Artly 官方描述了机器人磨粉、压粉、蒸奶与倒奶拉花，提供了厂商公开的产品路线案例。[S5] 本专题没有独立测试其性能，也没有取得适用于目标产品的机械设计或控制程序。

## 两种机械实现分支

| 方案 | 设计重点 | 量产代价 |
| --- | --- | --- |
| 固定工作空间的专用机构 | 为限定杯型、奶缸、轨迹和工艺设计自由度 | 可能简化机构，但要管理尺寸公差、重复定位、磨损和清洁 |
| 可编程多轴平台或机器人 | 通过多轴姿态完成取放、倾倒和动作组合 | 需要更多标定、工作空间管理、维护和运动安全验证 |

“专用机构可能降低复杂度”是工程判断，不能据此保证更低成本或同等拉花效果。具体优劣需要按同样杯型、奶泡与成功判据测试。

## 量产必须测整个任务

验收应覆盖奶泡制备、等待、定位、倒奶、结束、取放、残奶处理和清洁。只测电机重复定位精度，不能证明拉花成功率；只拍图案最好的一杯，也不能证明持续营业能力。

| 工程对象 | 量产验证关注点 |
| --- | --- |
| 工艺输入 | 奶种、奶温、奶泡质地、咖啡底、杯/奶缸规格与等待时间 |
| 机械一致性 | 加工与装配公差、标定、负载、间隙、磨损和重复定位 |
| 异常任务 | 杯位偏移、缺杯、掉物、溢出、机构卡滞和中断恢复 |
| 运营 | 补料、切换配方、清洁时间、失败重做、人员介入和备件 |
| 算法 | 同一测试集上的效果、输入边界、版本变化和失效处理 |

如果采用视觉或学习算法，训练数据、算法版本、相机与光照条件也属于产品配置的一部分。无需据此假定一定使用大模型；固定轨迹、传统视觉和学习方法都是不同设计选择，证据不足时不能宣称某一种必胜。

## 与联网和平台的关系

本地控制器和运动系统完成动作，联网可用于已证明需要的配方分发或运营记录。互联网与通用平台不会使缺少的机构、工艺和测试自动成立。当前没有证据证明 LimeIoT 能提升这一功能的工艺效果或量产成功率，因此不预设接入。

来源：S5 支持厂商案例；上述机械对比和验收表是工程分析与建议。目标产品的图案质量、连续成功率、机械寿命和成本仍无实测证据。
