# 开门自取与自动识别

开放自取设备先允许顾客进入共享货架，再识别其取走与放回的商品并结算。本章主要展开已查证的视觉自取路线；称重、RFID 等方法仅作为其他候选技术，未作供应商和性能比较。

365 的 PicoCooler Vision 官方说明：顾客通过受支持的卡、钱包或 App 方式解锁，拿取商品，系统以摄像头与 AI 识别，在关门后结算，并使用预授权限制风险。[V09] 这是厂商描述，没有独立测试识别效果或当前目标市场适配。

## 交易顺序不同

传统选品扫码可以在付款前知道固定订单金额；共享货架自取常需在顾客拿完后确定消费内容。预授权验证可用支付方式及一定资金条件，不等于最终金额已经结算。

| 阶段 | 业务与设备责任 |
| --- | --- |
| 开门前 | 确定顾客会话、支付/额度授权、货柜身份和进入条件 |
| 拿取期间 | 识别谁在何次会话中拿走、放回哪些商品，处理遮挡和多人干扰 |
| 关门后 | 确认会话结束，形成购物清单及证据，按支付产品完成结算 |
| 结果异常 | 区分低置信、识别矛盾、支付失败、门未关和顾客争议，明确复核与补偿 |

V09 说明增量授权受发卡方和支付类型限制，不能由此推断国内每种扫码支付都支持同一先开门后扣款流程。

## 识别系统的工程成本

视觉方案需要摄像头布局、光照、校准、商品模型/库、包装版本和事件数据，不只是给控制板增加一个“AI 开关”。算力可能在设备、边缘或服务端分配，实际位置与带宽、时延和隐私条件必须核实；厂商 FAQ 未足以证明所有部署细节或离线能力。

罐身相似、反光、软包装形变、双手遮挡、一次拿多件、取后放回、跨货架移动和补货调整均应测试。训练或演示中识别成功不能替代真实使用条件下的事件级和订单级结果。

## 数据、运营与验收

保留足够的订单与识别证据处理争议，同时明确摄像采集范围、访问权限、留存与清理。运营需要商品库维护、货架布置、补货正确性、模型/资源版本、异常人工复核与服务响应。

验收应记录可识别商品范围、拿放事件真值、错误与未知数量、整单金额差异、人工复核比例、端到端结算时间、支付失败和损耗。指标必须说明分母及测试条件，不能只展示模型准确率。

商品种类或识别条件不适合时，可以选择[格口柜](02-格口柜与受控领用.md)或[货道设备](01-货道出货与升降送达.md)，避免为采用 AI 而承担不必要的运行责任。
