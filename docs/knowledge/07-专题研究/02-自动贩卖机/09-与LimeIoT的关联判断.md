# 与 LimeIoT 的关联判断

自动贩卖机可以独立运行，也可以使用厂商已有交易与运营系统。当前缺少目标机型、合法可用接口、专用适配与实机验收证据，**不把 LimeIoT 作为本专题产品成立、收款或出货的必要条件**。

## 先成立的独立路线

成熟整机加供应商后台、独立的扫码交易应用加 VMC，或内部授权领用系统加格口/货道控制，都可以形成独立方案。具体选择取决于接口、支付产品、现场流程和维护合同，而不是仓库归属。[V02、V07、V09]

已有后台满足库存、补货和维护需求时，增加平台意味着新的集成、数据对账和长期维护责任，应先证明增量收益。

## 专业业务与通用设备能力

| 责任 | 主要内容 | 对 LimeIoT 的判断 |
| --- | --- | --- |
| 交易应用与经营主体 | 定价、订单、支付、退款、账单、客服与经营手续 | 需要专门业务系统与责任，不能由通用设备命令替代 |
| VMC 与设备供应商 | 机构、实时控制、检测、互锁、持久化与执行结果 | 按真实机型验证；不能凭平台发送成功声明交付成功 |
| 识别/工艺系统 | 商品识别、配方、食安与质量 | 属于专业产品能力，不因接入平台自动具备 |
| 通用设备管理 | 身份、状态、告警、配置和维护协同等 | 有明确多设备管理需求时，可作为后续增量价值评估对象 |

最后一行是候选关联范围，不是 LimeIoT 当前售货机支持清单。不能因为机器可以连 MQTT，就声称其支付、出货或运营已经接入。

## 从低耦合到较高责任的评估分支

| 候选范围 | 成立条件 | 应先提供的证据 |
| --- | --- | --- |
| 不集成 | 单机/供应商系统已满足需求，增量收益不足 | 产品流程、现有服务范围和总成本比较 |
| 只读状态与告警 | 有统一查看异构设备的实际需求，接口允许读取 | 字段来源、采样/上报时间、权限、断线/旧值及实机记录 |
| 受限维护协同 | 对停售、配置或维护有明确责任和授权 | 操作语义、设备就绪条件、审计、超时、恢复与版本兼容 |
| 交易驱动设备动作 | 专业交易系统确实需要形成可追溯交付任务 | 可信授权、订单/任务绑定、执行证据、幂等与未知处理、退款对账以及完整实机验收 |

这些是评估范围，可以组合；具体适配文档应按最终范围另建，不在没有目标接口时编造平台命令合同。远程动作也必须经过本地校验与保护。

## 当前项目证据

[总体架构](../../../03-总体技术架构.md)用于理解目标分工，[实施计划与进度](../../../24-实施计划与进度.md)用于判断当前实现与验收，[设备支持矩阵](../../../30-设备支持矩阵与证据台账.md)用于核对支持声明。本次在相关文档检索中未找到自动售货机、MDB/DEX 或支付出货闭环的专用验收记录。

现有通用软件测试不能替代这类实机结果，本次也没有新增驱动、支付服务、协议合同或设备支持状态。

## 改变当前结论的依据

需要具体需求与收益、目标设备接口与许可、责任划分、实现和异常路径测试、运营/售后与退出方案。具备这些证据后再比较 LimeIoT、供应商后台和独立应用的总成本与可维护性。

若最终只有一个本机交付流程，且现有系统已满足需求，维持独立产品路线是完整结论。相关专业流程见[交易一致性](03-交易支付与出货一致性.md)，来源见[台账](12-资料来源与证据边界.md)。
