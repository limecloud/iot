# 异构协议与适配器规范

更新日期：2026-11-01。状态：设计基线。平台保证核心语义独立，型号支持以 [30](30-设备支持矩阵与证据台账.md) 为准。

## 1. Port 与 Adapter

核心 Port 使用平台自己的设备引用、能力、观测、命令和错误。适配器负责发现、配对、能力描述、观测订阅、执行、健康检查与关闭；未支持的操作显式返回能力缺失，不要求每种协议假装支持相同生命周期。

| 接口职责 | 输入/输出 | 不变量 |
| --- | --- | --- |
| 发现 | 有期限扫描 → 候选及证据 | 候选不是已认领设备 |
| 配对/移除 | 当前授权、物理证明 → 绑定结果 | 不能无限开放入网 |
| 描述 | 精确型号/版本 → 能力子集及限制 | 不复制虚构能力 |
| 观测 | 原始帧 → 类型化观测/事件 | 保留来源、质量、时间 |
| 执行 | 已校验命令 → 发送阶段与后续结果 | 发送与完成分开 |
| 健康 | 连接、重启、资源、错误 | 辅助进程在线不等于设备在线 |

第三方 DTO、异常、厂商数据点和协议地址只在适配器内出现；核心错误稳定映射，必要原始证据以受控引用存放。

## 2. Zigbee

第一版固定一类 NCP 与固件，优先验证 CC2652/ZNP；主机侧 Rust 实现串口帧、请求关联、入网、访谈、ZDO/ZCL 能力映射、重连和设备 quirks。后续新增其他 NCP 驱动时复用核心 Port。

映射至少绑定 manufacturer/model、端点、Cluster、属性/命令、硬件/固件限制和映射修订。电池休眠、绑定/上报配置、重入网和网络备份分别验证；短地址变化不能创建重复设备。

网络密钥和协调器备份是敏感制品。未验证恢复时禁止宣称更换协调器可无损迁移。NCP 中的厂商 Zigbee 栈仍为外部依赖。

## 3. BLE

Linux 默认经 BlueZ D-Bus 适配；扫描和连接使用独立配额。广播传感器优先，只在实测支持时开展 GATT 控制和通知。

区分设备地址、隐私地址和逻辑设备身份。加密广播需当前用户提供或设备授权获取的密钥，无法解密时明确不可用；RSSI 不是可靠距离，更不是可信身份。

断连重订阅、通知丢失、MTU、配对状态和连接上限在型号档案中记录。协议要求的绑定密钥由密钥存储接口提供，不进入模型或公共证据。

## 4. 433

433 是频段称呼，适配需要明确频率、调制、脉冲编码、设备码和帧结构。接收、发送、双向反馈分别登记能力，不能由接收到遥控器推断可以可靠控制配对设备。

单向发送返回 `sent_only` 证据，设备实际状态通常为 estimated/unknown；没有确认通道时不能标 confirmed。滚动码、重放保护或缺少密钥的协议不承诺通用兼容。

接收器、收发器和 SDR 用途分开。rtl_433 可作为独立实验工具或符合许可的可选进程，不能将其实现无声明复制进核心。

## 5. Matter

分三项交付：Controller 认领并操作 Matter 设备；Bridge 将本平台设备暴露给其他 Matter 生态；Thread Border Router 提供 Thread IP 连通性。支持其中一项不能宣称三项全部实现。

标准栈在隔离模块或进程运行，以有版本的 IPC 合同连接。保存 Fabric、凭据与本地设备映射，验证 commissioning、订阅恢复、移除、共享及 Fabric 撤销。型号能力映射到核心物模型；不以 Matter Cluster 直接替代核心接口。

Matter SDK 可用不等于已获认证或商标使用资格，正式套件声明需有对应型号与认证依据。

## 6. 进程、权限与兼容

重依赖、FFI 或第三方运行时优先独立进程；IPC 限制消息大小、版本、权限和期限。平台管理生命周期、重启预算和健康状态，不给适配进程任意数据库、家庭密钥或宿主 Shell 权限。

适配器发布带支持矩阵、模型修订、映射修订、依赖版本、许可证和证据引用。升级后重新访谈或重映射必须可预览，不静默改变属性单位与命令含义。

## 7. 合同验收

同一套假设备合同验证所有适配器：发现不授信、非法命令拒绝、重复结果去重、超时保留未知、退出释放资源、重启不串设备、背压有界。协议专项再以真实设备验证，对未执行项保持明确缺口。
