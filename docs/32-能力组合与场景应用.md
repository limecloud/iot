更新日期：2026-11-04。状态：首版声明式事件组合已实现，完整组合体系仍为设计基线。目标是让开发者和商家将设备、多模态模型、内容与行为组合成产品；家庭与玩具为首批示范，核心支持后续空间扩展。

当前可运行范围见[正式事件组合合同](../contracts/composition.md)及[触摸伴读灯](../examples/compositions/reading-companion/README.md)：1–8个角色、精确模型预检查、现有事件/set规则编译、无执行预演、明确部署、原命令恢复和停用。`composition schema/compile/plan`为源码CLI入口，`npm run test:composition`验证真实网关软件链路。家庭网页在“自动化 → 使用组合包”选择模板或粘贴JSON，逐个绑定设备、预演和启用，共用同一规划器；先耐久保存原请求，再条件创建，丢回执只查询，停用复用原列表。网页检查为`npm run test:composition:web`，详见[网页合同](../contracts/composition.md#家庭网页)。首版没有持久包安装对象、签名信任、部署后模型锁定、模型调用或运动；下文的完整包、会话与物理组合要求不因首版编译器而视为实现。

上层[有限陪伴会话](../contracts/companion.md)另行组合已有模型任务，提供[积木小狗](../examples/companions/block-puppy/README.md)源码CLI样板：固定角色/模型、最多8轮和30分钟、准确交替历史、明确每轮、原键查询及停止清文。历史正文由调用者持有，会话账本只存摘要；不向事件DSL添加模型操作或第二套设备队列。`npm run test:companion`覆盖软件行为及原v1回归，家庭网页另提供“陪伴”入口，复用同一政策与客户端、录音和独立播放授权，见[网页会话](../contracts/companion.md#家庭网页)。Swift/Kotlin另提供原生陪伴SDK与音频页入口，复用已有回合、媒体与独立授权；角色和问答只在内存，后台清除上下文，恢复不补推理。检查入口为`npm run test:companion:native`，见[原生合同](../contracts/companion.md#原生客户端)。完整原生页面运行、真实输出质量、儿童/监护政策及实物组合仍待验收。

## 1. 平台原语

| 原语 | 含义 |
| --- | --- |
| Space | 家庭、教室、企业、健身等资源与授权边界 |
| Actor / Application | 当前人、机器、应用及有效委托 |
| Device / Module | 整机与可组合物理模块，拥有实际能力 |
| Capability | 属性、动作、事件、模型或媒体服务的正式合同 |
| Task / InteractionSession | 长任务与对话/多模态会话，各有生命周期 |
| Package / Deployment | 不可变组合定义及某空间的实际部署 |
| Evidence | 模拟、回放、实机、生态与交付的验证引用 |

设备不是仅有开关的家居实体；移动、清洁、交互、教育教具和健身设备通过能力与任务扩展。平台原语不承担课程设计、机器人导航、游戏剧情或专业咨询业务。

## 2. 品类能力地图

基础层：供电、电池、连接、身份、状态、更新时间、升级与健康。感知层：温度、距离、姿态、按钮、视觉、音频等。动作层：灯光、声音、显示、运动、机械与产品任务。智能层：文字、视觉理解、图像、ASR/TTS及有界Agent工具。应用层：角色、故事、玩法、清洁、陪伴、教育与场景服务。

同一能力可由不同硬件/模型实现，但实时性、权限、输入输出和反馈保证必须兼容，不能只因名称相同替换。

## 3. 组合包清单

| 字段 | 内容 |
| --- | --- |
| package_id / version / publisher | 稳定身份、不可变版本和发布者 |
| purpose / category | 用途、品类与场景 |
| dependencies | 精确模型、硬件/BSP、适配器、模型能力、内容和其他包 |
| inputs / outputs | 类型、单位、事件、媒体和结果Schema |
| permissions | 空间资源、设备动作、摄像头/麦克风、记忆、外发和预算 |
| compatibility | 软件、协议、硬件及生态限制 |
| constraints | 电气、机械、计算、时延、环境与适用人群 |
| behavior | 有界流程、任务、规则及允许的工具 |
| fallback / stop | 提供方失效、断连、取消和本地安全行为 |
| evidence / signatures | 正负夹具、实机范围、来源与签名 |

初期使用审核的声明式包。需要第三方可执行代码时，另行落实进程/沙箱、最小能力、网络/文件权限和资源预算，不能把安装包脚本当作自动可信代码运行。

## 4. 组合编译

读取清单 → 解析依赖与签名 → 查当前空间实际能力 → 类型/单位/接口匹配 → 物理与资源约束 → 授权/内容/外发政策 → 生成有界计划 → 模拟 → 必要批准 → 不可变部署。

软件能力校验与物理组合校验分开。电源、电流、重量/负载、重心、机械接口、运动范围和本地保护来自硬件资料与验证。飞行等能力仅在真实模块及具体组合经过验证后开放。

## 5. 组合玩具样板

“会对话的萌宠”：按钮/触摸或唤醒输入 → ASR → 角色与会话策略 → 文字/视觉模型 → TTS → 获准表情/灯光动作。角色内容、时长、媒体与记忆由产品政策控制；模型故障采用预置反馈和受限本地玩法。

“会飞的角色玩具/汽车”：发现真实飞行与结构模块 → 校验允许组合、供电和场地 → 模拟行为与用户选择 → 按监护/使用政策启用 → 本地控制器飞行。LLM只产生有界高层意图，不能控制电机闭环或代替安全停止。

“互动教具”：传感器/识图结果 → 适龄问题或故事 → 灯光/语音/动作反馈 → 会话作品。学习目标、评价与内容归教育应用，平台不把对话次数当作教育效果证明。

## 6. 任务与会话

包运行关联deployment_id、session_id、task_id和各原操作。支持步骤进度、输入等待、暂停请求、取消请求、部分完成和结果未知。会话代次变化使迟到模型/媒体结果失效，避免取消后继续播音或旧课堂结果进入新课堂。

确定性短联动使用DSL；清洁/移动等任务调用设备或专业应用服务；多模态生成由模型服务提供。流程可组合这些动作，但不得重建第二套设备状态与命令队列。

## 7. 场景扩展

家庭采用成员与监护政策；教室采用机构、教师、学生及课堂会话；企业采用管理员、操作员和服务身份；健身采用教练、参与者、设备与活动会话。核心Space与能力合同复用，专业数据、角色和行为由场景应用持有。

心理支持、教育和健身的专业结论由相应业务与服务方负责；平台支持合适内容、数据隔离、人工介入与转介接口，不将一般模型输出提升为专业事实。

## 8. 发布与验收

商家发布包不获得用户数据权；安装、授权、部署和执行分步骤核验。包更新展示新增权限、模型外发、内容、依赖和行为差异；撤回阻止新安装，已部署实例按明确安全策略处理。

验收涵盖缺模块、类型/单位不符、物理不兼容、预算耗尽、权限变化、提供方失败、会话中断、停止与取消竞态。模块单独通过不意味着任意组合通过，组合结果写入型号与包证据矩阵。
