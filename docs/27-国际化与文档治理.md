# 国际化与文档治理

更新日期：2026-11-01。状态：设计基线。当前工程文档使用简体中文，首期产品资源规划支持英文与简体中文。

## 1. 语言与资料

机器ID、字段、错误码、状态、路径、operation_id和单位代码固定，不随语言变化。模型/包的显示资料、系统消息、用户内容与生成内容分开存放。

产品使用语言登记作为唯一来源，目标路径为 `contracts/i18n/locales.json`；初期en为默认和最终回退，zh-CN为另一开放语言。用户原始内容可使用其他语言，不代表增加产品界面正式语言。

前端沿成熟i18n方案，Go/Rust采用各自合适的本地化库与统一消息ID/参数合同。日期、数字、时区和单位显示由上下文决定，不把显示文本写回机器值。

## 2. AI优先知识入口

`llms.txt` 提供按任务阅读的入口，`docs/catalog.json` 提供稳定文档ID、路径、职责与状态；`docs/requirements.json` 提供需求、故事、用例和专项文档映射。它们是文档导航与设计数据，不是线上当前权限或工具可用性目录。

Agent先读取索引与具体章节，再获取所需Schema和夹具，避免每次加载整套文档。文档状态必须准确，规划端点不能被当作已部署API执行。

## 3. 正式合同与示例

实现阶段的机器合同由 `contracts/` 管理，文档引用生成或校验的内容。当前 `docs/examples/` 保存设计示例及负例；迁入正式合同时同步消费者和校验入口，保持语义唯一。

Schema、知识、工具方法和业务执行分责：Schema描述输入输出；知识解释适用场景；方法组织任务；正式用例判断当前授权并执行。文档、Skills和安装包均不持有第二份设备状态或权限。

## 4. 文档维护

每篇明确职责与状态，跨篇用链接引用事实。需求在01、模型在05、通信在06、适配在07、权限在12、API在16、验收在23、进度在24、设备证据在30、生态在31、组合在32、模型媒体在33维护。

文档直接描述当前设计，保留必要的决定、证据和限制，不记录对话过程。新能力同时更新产品需求、领域归属、协议/工具、任务、失败/恢复、验收和实施计划。AI生成内容需与源资料和实际状态核对。

## 5. 公开与私有

公开指南与示例不包含生产凭据、客户正文、未授权设备样本、儿童媒体或内部敏感SOP。真实证据按可见性发布脱敏摘要与受控引用，文档可公开不等于原始资料可公开。

模型提供方、角色内容和生态资格的条款按实际版本引用。外部链接不可访问时说明证据边界，不推断其不存在或开放权限。

## 6. 验收

检查本地链接、目录与需求覆盖、编号唯一、图代码围栏、JSON/YAML解析和示例不变量。产品阶段再验证语言装配、回退、错误参数、时区、并发上下文与GUI/TUI同义表现。
