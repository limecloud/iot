# AI 与 Agent 接入设计

更新日期：2026-11-01。状态：设计基线。AI-first 贯穿研发与产品，统一模型服务见 [33](33-多模态模型与媒体服务.md)，API/CLI 合同见 [16](16-API事件与CLI规范.md)。

## 已实现的本地规则草案

当前实现文字需求 → Ollama 适配器 → 耐久草案 → 既有 DSL 校验/预演 → 用户明确部署。正式入口为 `drafts.create/list/get/resolve`，CLI、家庭 PWA 与 Swift/Kotlin 原生端共用网关合同。模型未配置时不影响控制和手工规则。它尚不构成通用 Agent 循环、统一模型目录、语音/视觉或媒体服务。

`RuleInference` 是运行时消费的窄接口，Ollama 和 HTTP 类型不进入领域核心。模型只能返回事件触发与属性设置，条件为空；平台分配 `ai-<draft_id>` 规则 ID，重新检查设备引用、可写属性和值域。模型无工具、MQTT、部署或宿主访问权限。冻结上下文只有绑定设备 ID、模型修订和物模型，最多 16 KiB；适配器向模型进一步投影为设备的完整事件路径、可写属性路径和值Schema，输出Schema绑定各设备与路径。状态、历史、凭据和模型元数据不传入推理；冻结上下文变化则拒绝结果。

创建前耐久保存调用意图，同键同参返回原记录，异参冲突；最多保存 128 条。状态为 `running/completed/rejected/unknown/expired`。重启中的调用、断流及推理超时保持 `unknown`，迟到的成功输出过期，不重调提供方。模型与提供方、请求/上下文摘要、规则修订及真实可得的 token 用量一并记录。客户端仅保存恢复原记录的空间和键，提交前存储失败不发送；修改需求会使原预演证明失效。

仅允许回环/RFC1918/IPv6 ULA 的模型地址，拒绝公网与链路本地地址、代理和重定向。单并发、无队列、至多 90 秒和 1024 输出 token，限响应为 64 KiB。完整配置和检查见[开发入口](../deploy/dev/README.md)与[NAS 可选模型](../deploy/nas/README.md)。夹具、真实模型和物理设备分别验收，当前证据统一见[进度](24-实施计划与进度.md)。

## 1. 调用者与责任

| 调用者 | 目标 | 执行归属 |
| --- | --- | --- |
| 编码 Agent | 理解需求、生成、构建、回放与验证 | 仓库与实验环境的明确工具和权限 |
| 适配 Agent | 分析样本、提出协议假设、维护映射 | 实验流程及实机证据 |
| 用户任务 Agent | 控制、诊断、配置规则和跟进任务 | 当前空间的正式领域用例 |
| 玩具/机器人应用 Agent | 对话、感知和有界行为组合 | 应用会话、设备任务与本地安全控制 |

平台提供模型、工具、上下文与任务合同。外部 Agent 宿主和应用自己的编排可独立使用；不强迫所有开发者采用某个通用 Agent 框架。平台内置的有限任务循环使用同一受控工具接口，不另建超级权限通道。

## 2. AI-first 开发链

需求与场景 → 机器文档索引 → 正式 Schema 与例子 → 可用板卡/型号 → 生成或修改 → 本地静态/合同检查 → 模拟 → 回放 → 实机 → 差异与证据 → 交付。

为 Agent 提供稳定章节、机器目录、operation_id、错误码、能力限制、必要上下文和验证入口。清单区分规范已定义、工具已实现和硬件已验收，Agent 不能从文件存在推断功能可用。

## 3. 工具定义

每个工具声明输入/输出 Schema、当前身份、space_id、application_id（如适用）、资源范围、合同修订、是否有副作用、期限、预算、幂等及恢复操作。发现结果按当前权过滤，发现本身不授予执行权。

首批工具族：模型读取、设备发现/读取、命令准备/提交/查询、规则校验/模拟/部署、任务查询/取消、型号诊断。后续加入媒体、模型调用和组合包工具。MCP 与 CLI 并行适配正式用例，MCP 不依赖运行 Shell 或解析 CLI 文本。

## 4. 任务闭环

```mermaid
flowchart LR
  I[意图] --> C[确定空间主体和范围]
  C --> D[发现能力与读取当前事实]
  D --> P[生成有界计划或草案]
  P --> V[校验 模拟 差异与政策]
  V --> A[取得所需精确授权或确认]
  A --> E[正式用例执行]
  E --> R[原操作结果与证据]
  R --> N[完成或按合同恢复]
```

普通已授权低风险控制可以直接执行，不给每次查询或开灯增加统一审核。组合包安装、权限扩张、媒体外发、付费模型及高后果动作按相应政策取得明确批准。确认绑定主体、空间、具体参数摘要、修订和期限，不能由模型自报已确认。

## 5. 模型、上下文和记忆

模型目录按能力选择本地或云端提供方，数据外发和费用必须满足应用/空间政策。Ollama 不响应时，可按预先允许的同等数据政策降级；不得无声改用外部云。

输入采用有界当前状态与必要资料，模型不直接读取数据库、凭据、全屋媒体或全量历史。文档和设备自报文本为数据，不能覆盖系统工具政策。跨应用、空间和使用者会话的记忆默认隔离；长期记忆需用途、留存和删除规则。

儿童、课堂和陪伴应用使用对应主体及监护/机构政策；情绪支持应用可提供表达、陪伴和专业服务转介，专业诊疗或心理咨询业务由具备对应条件的服务方负责，平台不从一般对话推断诊断结论。

## 6. GUI/TUI 与宿主适配

第一层优先在当前 Agent 宿主完成任务：分步输入、列表、差异、确认、进度、结果和恢复；支持时提供 MCP Apps 等端内任务界面。第二层为实际可用的内置浏览器，第三层为受信资源 URL；按具体缺失步骤回退并保留原操作上下文。

CLI 输出稳定 JSON/NDJSON 和退出码，TUI 使用同义文本和差异，GUI 支持媒体、表单与组合图。宿主类型不决定业务角色；不同端分别认证、共用授权与用例。仅显示一个链接或 JSON 不证明需要交互的任务已经完整适配。

## 7. 预算与终止

每任务设置最大工具调用、步骤、并发、token/媒体/费用和总时间预算；耗尽后保留进度，不能持续自我重试。模型请求取消、应用会话结束、任务取消和设备安全停止分别处理。

工具发出后响应丢失，保存原 operation/task/command 引用，先查询原结果。Agent 不因换模型、换会话或用户重复表达而自动创建新的非幂等副作用。

## 8. 验收

按“角色 × 任务 × 宿主及版本 × 本地/远程”记录证据。验证幻觉能力、设备名歧义、提示注入、撤权、跨空间数据、云外发限制、预算耗尽、错误结果、断流与原操作恢复；同时验证模型关闭后基本控制和已部署规则仍运行。
