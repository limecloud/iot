# 咕团网关支持审查与软件验收

[English](gateway-support.md)

2026-11-03。范围为本地网关软件及其消费者。咕团仍需要独立的产品固件、硬件和实机验收；以下结果不构成已完成零售玩具的声明。[机器证据与源摘要](gateway-verification.json)。

## 已补齐的通用能力

| 能力 | 当前行为 | 依据 |
| --- | --- | --- |
| 实时业务事件 | 原 ingest 完整校验后，严格投影设备、模型、会话、原事件与正文摘要；提交成功才通知，重复和历史事件不形成新业务投影 | [双语事件合同](../../../contracts/device-events.md) |
| 分阶段多设备计划 | 创建草稿零命令，明确启动；同阶段全部 child 原子受理，等待全部结果再受理下一阶段 | [双语计划合同](../../../contracts/execution-plans.md) |
| 长任务完成 | submitted 只证明输入提交；计划还核对任务、代次、步骤、当前会话及原事件摘要 | [任务事件](../../../contracts/execution-plans.md#类型化任务事件) |
| 恢复与互斥 | 丢响应只查原键；Running 重启后转 Unknown 且不重放；启动过的计划明确 release 前保留占用 | 原命令账本与计划记录 |
| 持久化 | 首次写入计划才采用快照 v12；旧 v10/v11 未使用功能不隐式升级；篡改与晚 SQL 失败不发布半次修改 | 5组 Store 专项 |
| 控制台动作消费者 | 两套活跃远程工作台支持 Schema 2 参数与动作可用性、模型摘要、风险确认、完整回执和原键恢复 | [官网维护验证记录](https://github.com/limecloud/iotweb/blob/main/docs/06-咕团生态案例与接入.md) |

计划仅用于本地所有者 HTTP/CLI，最多8台、16步、15分钟；子命令继续限30秒。管理操作的 expires_at 采用合同要求的规范 UTC 文本；设备事件保留原 RFC3339 文本及其摘要。云 relay 的动作白名单没有扩展。

## 仍需产品工程的工作

1. **设备安全运动。** 设备侧原子控制代次隔离、拒绝旧命令/时间线、租约到期关闭驱动、看门狗、障碍与实体停止。仅把 stop 插入队列前端不能阻止迟到旧命令重新启动。cancel 只阻止未来阶段，不证明物理停车。
2. **同步节目。** 原有 ready 和在线信息不等于节目就绪或时钟证明；需要时钟偏移、不确定度与漂移、预加载、输出延迟及多台实测。阶段屏障不等于节拍同步。
3. **产品固件。** 当前C SDK只有有限属性和单整数事件子集；S3完整动作、结构事件、电机、音频、相机和并发驱动仍需实现。
4. **消费者入网。** 已绑定设备CSR签发不代替按键挑战、物理认领、所有权转移和产品配网。
5. **产品应用与AI。** 队伍、场次、角色、计分、适龄策略、家长授权、费用与媒体政策归产品层；完整ASR/TTS、对话和视觉流程尚未交付。
6. **长期容量。** 计划128、管理操作1024、命令4096、业务事件去重4096及有界事件日志不是无限档案。归档、退休边界与回收需独立设计，不能逐帧逐拍生成耐久命令。

未操作生产IoT服务，未升级已有网关数据库，未执行Git提交、推送或发布。软件模拟的 `hardware=false`、`motion=false`、`beat_synchronization=false`。
