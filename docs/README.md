## 1. 阅读方式

接入与恢复的当前结果先读 [24状态总览](24-实施计划与进度.md#当前接入与恢复状态)。C3生产适配器宿主、worker边界及 [换证后常规恢复](24-实施计划与进度.md#438-c3同进程身份与跨进程执行记录恢复) 分别取证；后续 [恢复读取与控制提交故障](24-实施计划与进度.md#439-c3恢复读取与控制回执提交故障) 的3条旅程覆盖12项启动拒绝和4项控制回执提交故障。[OTA日志跨恢复提交故障](24-实施计划与进度.md#442-ota日志跨身份维护与进程恢复的提交故障) 的16项软件矩阵已通过，入口为`npm run test:firmware:ota-recovery`；真实安装、启动健康、芯片掉电与目标系统仍按 [23第5.2节](23-测试策略与验收矩阵.md#52-换证后新进程与已有执行记录的连续性) 验收。入口与平台替代范围见 [固件运行期说明](../firmware/README.md#运行期凭据保护)，完整平台仍在开发。

第一次接触物联网，先从 [IoT 入门知识库](knowledge/README.md) 开始：按高频问题、基础、标准生态、架构、场景、成本与资料工具分类，配套架构图、流程图、时序图和小米官网实例。知识库解释概念，正式规范、当前进度和型号证据仍在本页所列的唯一来源维护。

产品集成案例：[Gootuan 咕团](integrations/gootuan/README.zh-CN.md)（[English](integrations/gootuan/README.md)），说明独立玩具产品与通用平台的职责，并提供按当前正式合同验证的触摸与双虚拟灯案例。语音、视觉、同步运动和实物产品仍按各自工作包验收。

Agent优先读取根 [llms.txt](../llms.txt)、[文档目录 catalog.json](catalog.json) 和 [需求映射 requirements.json](requirements.json)，按任务获取具体规范与示例。产品与规划阅读 01、03、17、24、29；设备开发阅读 05、06、08、12、13；网关开发阅读 04、07、09、10、14；客户端及 Agent 阅读 11、15、16、27；硬件和适配阅读 19、20、30；验收和交付阅读 18、21、22、23、28。

本套文档学习 Lime Cloud 的编号目录、领域事实归属、合同驱动、多端共用用例、原操作恢复、需求追踪和真实验收方法。文档内容围绕 IoT 重新设计，未复制 Lime Cloud 的商业领域、部署限制或门户数量。

## 2. 设计基线

| 类别 | 内容 | 状态 |
| --- | --- | --- |
| 产品 | AI-first 智能物联与能力组合平台，家庭/玩具首批，向企业/教室/健身扩展 | 用户已确认 |
| 核心 | 自研物模型、MQTT 应用报文、ESP-IDF SDK、Rust 网关、事件总线、设备状态机、DSL、身份与 OTA 管理 | 用户已确认 |
| 边界 | 外部组件经适配器隔离，基础运行不深度依赖 HA/ESPHome/zigbee2mqtt | 用户已确认 |
| 系统分工 | 建立在现有设备OS/框架之上，首期ESP-IDF；Rust网关为Linux用户态应用核心 | 用户已确认 |
| 电视终端 | 统一设备/命令核心；显式分区原生与适配动作，离线不回退 | 跨模型软件闭环见4.19；实际JVM/假ADB组合及新预检通过见4.22。Android独立启动、实际AOT及安全组2项已有证据，完整入口仍受阻，见 [4.24](24-实施计划与进度.md#424-独立启动诊断与android安全组端上验证)；当前交付依赖见4.21，实机跳过 |
| 可选音频终端 | 存量音箱经 DLNA 承担播放；外部采音与 AI 处理可独立组合，保留原厂服务 | 设计与边界见36；实施状态与型号证据分别见24/30 |
| 接入路线 | 原生设备开发优先；存量设备通过标准、公开接口或厂商授权逐型号验证 | 产品基线 |
| 网关 | 轻量 Linux 版与 N100 算力版，共用核心 | 用户已确认 |
| AI | 统一文字/视觉/图像/语音服务，提供方独立；Agent优先的工具和GUI/TUI | 用户已确认 |
| 商业 | 开发者与商家发布能力组合、设备套件和技术服务 | 用户已确认 |
| 名称 | LimeIoT / 青柠物联，仓库为 limecloud/iot | 项目基线 |
| 工程 | Rust/Tokio/SQLite；云端 Go/Gin/MySQL；React/TypeScript/PWA | 工程基线 |
| MVP与部署 | 桌面互动环境灯三节点；NAS私有化版与Cloudflare + Railway上的LimeIoT官方云服务版；可选接入LimeCloud | 产品方案；实际实现、部署与验收见24 |
| Web与源码范围 | 私有品牌官网；开源开发文档、通用Console/Admin及NAS家庭界面；官方专有商业运营与生产配置私有 | 仓库边界；实际实现与验收见24 |
| 许可 | Apache-2.0 | 项目基线 |

自主可控指核心应用与生命周期可独立演进，不承诺芯片 BootROM、无线二进制组件或厂商 NCP 栈全部开放。系统分工见03，接入事实与限制见02/07/31，工程取舍见26。

首个MVP按29→19→14→21→22→24阅读，分别确定演示、采购、平台集成、monorepo、NAS/云部署和排期；规格及价格假设不等于已验证硬件支持。
