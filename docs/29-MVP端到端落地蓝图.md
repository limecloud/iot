# MVP 端到端落地蓝图

更新日期：2026-11-03。状态：MVP设计基线，灯光/按钮模拟链路已有软件验收，环境节点已补正式模型、SHT3x驱动和C3角色。最新三节点软件结果见[实施进度](24-实施计划与进度.md)，实机按用户要求跳过，完整NAS/官方云产品仍待交付。首批场景为“桌面互动环境灯”：以Agent优先开发链为入口，使用可采购低压硬件、NAS本地网关和可选云，验证从开发到家庭运行的完整链路。

## 1. 最小产品

一个空间、一个运行在NAS上的Rust网关、一个可替换MQTT Broker、模拟器和三类低压样机：温湿度、按钮、灯光。硬件采用3块ESP32-C3-Zero-M，外接SHT30、独立按钮和8位WS2812B灯环，详见 [19](19-硬件选型采购与BOM.md)。复用NAS时，首批物料按250–500元预算准备，实际价格待询。

具备物模型、配网认领、观测、命令、规则、原操作查询、CLI和NAS本地家庭PWA。官方平台同时交付官网、开发文档站、用户/开发者控制台及运营管理后台；这些入口与NAS本地界面各有任务和认证边界。AI只实现文字到规则草案/诊断解释，提供Ollama与LimeCloud模型适配路径；后者以真实服务开通和本人授权为前提。部署后的规则不调用模型。

第一组组合将按钮、温湿度和灯光组成“会响应环境的桌面小伙伴”，可换外壳而不改核心。语音/摄像头、机器人底盘、飞行、多生态桥接和商业市场进入后续阶段。模型平台的多模态方向保持不变，首期先验证一种真实模型能力。

当前温湿度为只读观测：10秒采样、15秒过期，缓存保留原采样时间。新NAS可选择三节点配置，Web及原生客户端源码按单位显示读数。“温度越过28℃”已有CLI/API及三端单步阈值表单实现，使用1℃滞回和新鲜采样，准确行为及证据见[自动化合同](../contracts/rules.md#属性阈值边沿)与[实施进度](24-实施计划与进度.md)。物理认领、自动续期及原生端上验收尚未完成。

原生板卡需具备明确资料、可用ESP-IDF支持、烧录/恢复与供电条件，设备选择按 [19](19-硬件选型采购与BOM.md) 执行。本切片可在没有小米、华为等商业生态账号或接口时独立验收；存量设备与生态互通在原生链路成立后，按各自实际路径扩展。

## 2. Agent任务入口

输入目标：“在C3-Zero-M板卡上实现温湿度和按钮，按下按钮时开灯；温度上升越过28℃时将灯光亮度设为30%，全部本地执行”。温度阈值只用于演示，不具有健康判断意义。首版灯光只要求开关/亮度，颜色是固定表现，不增加未实现能力。

Agent读取 `llms.txt`、目录、对应需求和机器样例，核对当前已实现工具；生成模型与产品绑定后进行模拟，再进入实机。自然语言只负责产生可校验草案，部署必须经过正式工具用例。

Agent必须输出：变更、验证、失败/跳过、硬件/授权缺口、制品与下一步。需要人工接线或按物理配网键时给出精确步骤，不将工具缺失转换成假成功。

### 2.1 五分钟产品演示

1. 在NAS本地页面或CLI认领3个节点，看到当前温湿度、按钮和灯光能力。
2. 对Agent说“按下桌面按钮就开灯”，读取草案，模拟一次，再部署固定版本。
3. 按实体按钮，灯环点亮；查看同一`run_id`下的触发、`command_id`及设备驱动回执。
4. 通过模拟事件展示温度边沿规则，明确标记模拟；实机传感器另外记录真实读数，不把模拟当作真实环境变化。
5. 切断互联网并关闭模型，重新打开NAS本地页面，实体按钮和已部署规则仍可用。
6. 恢复网络后在远程PWA查询状态和控制结果，再演示一次签名升级与失败回滚。OTA与恢复演练可以独立于五分钟展示完成。

### 2.2 两个产品版本

| 方式 | 家庭内 | 服务端 | LimeCloud |
| --- | --- | --- | --- |
| NAS私有化版 | Rust网关、Broker、SQLite、本地家庭PWA和制品 | 家庭MVP在NAS运行；私有集中控制面复用同一Go/MySQL及所需Console/Admin制品 | 可关闭；本地初始化、控制、规则、升级不需要其账号或服务 |
| LimeIoT官方云服务版 | 轻量网关/常开Linux主机，也可复用NAS | 官网/文档/Console/Admin在Cloudflare；Railway Go/MySQL、R2由官方维护 | 官方云优先接OIDC登录，按实际开通接Models；权益/支付后续按需 |

官方云用户不必拥有NAS或自行部署Go/MySQL；首期仍需要家庭网关承接本地规则与设备执行。NAS用户可以选择关联官方云，但不关联也可验收私有化核心。LimeCloud是可选能力提供方，不是产品第三版；LimeIoT拥有自己的设备与家庭领域。Web入口职责见 [15](15-客户端与交互设计.md)，完整私有化控制面、网络和存储合同见 [14](14-云端服务与边云协同.md)、[22](22-本地开发部署与运维.md)。

官网与文档中心在私有 `iotweb` 仓库维护，共用官网域名与构建；通用 Console/Admin、NAS 界面、工程规范与运行核心在开源 monorepo。官方云复用这些核心，商业运营扩展按需私有。自部署必需功能保留开源，许可边界见 [25](25-开源许可生态与商业化.md)。

## 4. 连续验收脚本的业务步骤

1. 初始化独立实验空间并载入灯光、按钮、温湿度模型。
2. 启动模拟设备，核对身份、模型、快照、时间与观测质量。
3. 用CLI提交灯光目标，取得原command_id；GUI和Agent工具查询同一结果。
4. 重发相同幂等键与请求只取得原操作；不同参数触发冲突。
5. 部署按钮触发灯光规则，注入事件，核对run_id和command_id；重复及历史事件不重复触发。
6. 接入实际ESP并复现任务，记录板卡、固件、驱动和实际反馈。
7. 断互联网与模型，保留本地控制和规则；重启网关并核对快照和任务。
8. 注入发送后失联，确认客户端保留unknown并查询原操作，不换键重发。
9. 测撤销、过期、坏值、旧会话、磁盘不可写与错误模型。
10. 执行升级与回滚，收集制品及启动证据，完成脱敏报告。
11. NAS重建容器后身份、规则和原操作保留；在阻断公网时打开本地页面并控制灯光，检查浏览器无必需CDN、云字体或在线认证依赖。
12. 在第二个隔离空间测试远程列表、订阅和命令越权被拒；网关离线时远程命令不显示已执行，也不在重连后突然补发。
13. LimeCloud模式验证Code+PKCE登录、精确回调、账号绑定与撤销；LimeCloud不可用时已有本地所有者仍能控制。若Models已开通，另验数据授权、费用和原调用恢复。
14. 在同一NAS/主机的隔离环境启动私有Go/MySQL控制面，验证使用本地制品存储且无Cloudflare/Railway依赖；数据库与网关执行事实不混用。
15. 匿名从官网进入开发文档，读取原始Markdown、机器目录和指定版本合同；分别按NAS/官方云指南完成模拟和入口接续。
16. 使用普通用户、开发者和运营员分别访问Console/Admin；核对独立会话、管理API拒绝、当前角色撤销和运营员没有家庭默认控制权。

当前 `tests/e2e.test.mjs` 已覆盖设备发现、模拟控制、幂等与冲突、按钮规则、重复/历史事件、重启恢复及未知回执子集；其余实机、OTA、NAS/云与身份任务仍待实现。具体运行方式见 [本地开发](../deploy/dev/README.md)，不将模拟结果提升为完整MVP交付。

## 6. 完成与扩展

完成MVP需要真实原生设备、最小Agent任务和故障恢复同时有证据。之后新增一个Zigbee或BLE灯光映射，证明相同模型无需修改核心；再输出Matter Bridge至指定Apple/Google环境。多模态和玩具包根据同一合同逐项增加，范围见 [24](24-实施计划与进度.md)。

| 验收目标 | 首轮测量方式 |
| --- | --- |
| AI开发友好 | Agent从机器入口完成模拟设备发现、规则生成/校验/模拟/查询；人工接线和批准单独记步数 |
| 本地响应 | 固定网络下100次按钮任务，记录端到端p50/p95；p95≤500ms作为实验目标，未测前不作为承诺 |
| 离线自治 | 公网与模型关闭24小时，规则和本地页面可用；NAS重启后恢复，无历史事件重复执行 |
| 设备可靠性 | 3个节点连续运行72小时，记录断连/内存/错误；人工确认灯光与驱动回执边界 |
| 升级安全 | 双槽体积满足、坏签名拒绝、下载中断、启动失败回滚与身份保留均有实机证据 |
| 云与私有化 | 同一源码/合同完成NAS和Railway部署验收；云断连、代理重连和跨空间拒绝有记录 |

这些是首轮实验门槛，不代替量产、儿童玩具认证或长期SLA。排期和当前完成状态只在24维护。
