# 可观测性与可靠性

更新日期：2026-11-01。状态：目标与测量方案，所有数值均待实测验证。

## 1. 关联与证据

贯通 request_id、operation_id、command_id、task_id、rule_run_id、invocation_id、session_id与trace/correlation引用。一次用户或Agent任务可以关联多条设备与模型操作，原身份保持可查询。

日志保留空间、模块、阶段、稳定错误和安全引用；不记录私钥、Token、完整恶意负载或无必要的音视频。设备采集时间、网关接收时间、云同步时间分别保存。

## 2. 指标

| 领域 | 指标 |
| --- | --- |
| 网关 | CPU、内存、队列深度、线程阻塞、存储延迟/空间、重启 |
| 设备 | 当前健康、最后观测、过期属性、连接/握手失败与丢包 |
| 命令 | 受理/发送/确认耗时、unknown、期限、拒绝与原操作恢复 |
| 总线/任务 | 积压、慢消费者、游标差距、租约、重试预算与取消阶段 |
| 规则 | 触发、去重、冷却、循环阻断、执行步骤与部分失败 |
| 模型/媒体 | 首片段/完成延迟、并发、预算、用量、部分/未知、媒体字节和丢帧 |
| 生态 | 授权失效、映射错误、订阅重建、云依赖和回声抑制 |
| OTA | 批次、校验、安装、启动确认、回滚和恢复 |

## 3. 初期测量目标

| 项目 | 目标假设 | 测量条件 |
| --- | --- | --- |
| 本地命令受理 | p95小于100ms | 指定硬件、有限并发、只计算耐久受理 |
| 设备控制反馈 | 原生灯光p95小于500ms | 局域网、指定固件，分别记录各阶段 |
| 简单规则调度 | 有效事件到命令受理p95小于100ms | 固定规则数量与负载 |
| 单空间规模 | 先验证50逻辑设备、10条活跃规则 | 同时声明上报频率、大小与协议分布 |
| 离线自治 | 72小时连续实验 | 断互联网、云和模型，保留局域网络 |
| 套件长稳 | 至少7天固定版本soak | 另做断电、弱网和故障注入 |

这些是实验退出目标，不能用作尚无证据的营销指标。无线休眠、单向433和模型推理不适用同一控制延迟承诺；模型每模态、模型版本和硬件单独测量。

## 4. 资源与过载

内存队列、设备速率、订阅数、任务并发、模型token/媒体和磁盘都有预算。按优先级保障身份、停止/控制和回执，普通telemetry可合并，媒体/推理可限速或拒绝。

模型与媒体进程有CPU/内存/磁盘限额，不让OOM影响控制内核。磁盘满时停止需要耐久性的受理，禁止吞掉保存错误后继续返回成功。

## 5. 恢复目标

关键状态以已提交事务和设备外部事实为边界，RPO/RTO按实际备份与恢复实验确定。单机存储不保证硬件损坏零丢失；SQL恢复也不撤销物理副作用。

恢复演练核对原操作、撤销水位、密钥、模型/映射、定时器及设备实际快照。恢复后观察到的旧状态必须标记时间与质量，不能因数据库可读就判设备恢复在线。

## 6. 告警与诊断

告警依据持续时间、影响范围和可执行下一步，避免对每个模型超时重复通知。诊断输出结论、检查项、观察时间、覆盖完整性和原证据引用；来源故障不补零，不把当前页冒充全量。

## 7. 发布核对

性能报告附源/制品摘要、工具链、硬件/固件、负载分布、模型、统计窗口与失败样本。新变更只有影响这些指标或暴露未解决问题时才扩大重复测试范围。
