## 3. 非功能门槛

NFR-01 验证独立核心和可替换假适配器；NFR-02 注入事务/发送/执行/回执崩溃；NFR-03 测洪峰、慢消费者、磁盘与推理预算；NFR-04 测跨空间、假身份、撤权和旧凭据；NFR-05 测日志、模型上下文、媒体和导出；NFR-06 核对工具链、SBOM与制品；NFR-07 验证不兼容模型、协议、映射和控制器版本。

原生开发链需在无第三方商业生态账号或云接口时完成模拟、实机接入、本地控制与升级验收。生态适配分别验证实际接口资格、能力和撤销行为；OS移植、标准SDK编译或样本回放通过均不能代替该生态验收。

## 4. 必测故障

断互联网、断模型、断设备、网关重启、设备掉电、重复/乱序、时间回拨、证书失效、密钥轮换、权限撤销、错误签名、更新中断、未知命令、取消竞态、包越权、提示注入、跨会话迟到结果和硬件替代料变更。

飞行、移动和清洁等产品增加设备本地急停/限位/电量/断连测试。专业场景由应用定义额外标准，平台的通用测试不能代替产品适用的认证或专业验证。

首个MVP另外验证NAS容器重建/宿主重启、阻断公网后的本地页面、SQLite本地卷及备份恢复、WSS断连原操作恢复、Railway迁移失败阻断、Worker API不回退HTML。x86_64/ARM64分开记录实机证据；LimeCloud分别记录OIDC和Models的真实联调状态，不以登录通过代替模型授权/费用验证。具体连续任务和测量目标见 [29](29-MVP端到端落地蓝图.md)。

## 5. 证据格式与完成声明

记录需求/用例、源提交、构建输入与摘要、环境、工具/依赖版本、型号/批次/固件、主体/空间、步骤、预期、实际、失败、跳过、原操作引用和证据文件摘要。敏感材料单独受控，公开结果脱敏。

状态为 pass/fail/skipped/blocked/not_run；跳过不计通过，模型生成报告不替代原始结果。只有对应层次和范围满足门槛，才提升当前状态；所有扩展品类与生态分别验收。

以下为 FR-32 / UC-23 的验收计划，实际结果只在 [24](24-实施计划与进度.md)、[30](30-设备支持矩阵与证据台账.md) 登记。架构和能力边界见 [34](34-电视终端与AndroidTV接入.md)。

| 编号 | 验证内容 | 通过标准 |
| --- | --- | --- |
| TV-A01 | 发现、物理授权和身份归并 | 发现不授信；Agent 与 ADB 经批准绑定同一逻辑设备，不能按 IP 自动归并 |
| TV-A02 | API 23 终端 | 安装/启动、依赖与实际 ABI、TLS/CA、权限变化分别实测；手机 APK 构建不替代 |
| TV-A03 | 网页基础遥控 | 手机/电脑视口可完成方向、确认、返回、主页及允许的应用启动，逐项核对实机 |
| TV-A04 | 属性与结果 | 精确模型与实际能力一致；仅动作模型须验证空属性快照及各端兼容；音量/静音读写分别验证，不补假值；输入提交、实际回读和界面结果不混淆 |
| TV-A05 | 按键顺序、去重和期限 | 重复投递不重复执行；过期/旧会话拒绝；断线、重启和刷新不补发旧按键 |
| TV-A06 | 唯一执行路径 | 分别统计 MQTT/适配器发送，命令只交给所选端；持久化失败零发送，标记后中断及丢回执保持 unknown；路由更新、重启及迟到证据不导致跨端补发 |
| TV-A07 | 失权与隔离 | 撤销设备或 ADB 授权、跨空间和未授权应用被拒；网页不取得设备私钥或任意 Shell |
| TV-A08 | 离线、恢复和待机 | 无公网可完成已授权本地控制；重连重新核验；离线不推断关机，唤醒单列能力 |
| TV-A09 | 可选媒体和联动 | 截图/预览独立权限及限额；观影联动逐设备保留结果，不声称跨设备原子完成 |
| TV-A10 | 绑定与模型兼容 | 首次绑定、模型换绑及恢复执行一致校验；不支持的路径、输入、输出或completion在业务调用前拒绝，副作用为零；并发旧修订不得覆盖新绑定 |
| TV-A11 | 已有空间接入与撤销 | 宿主候选不自动绑定；精确绑定/模型修订、原键恢复、ABA与容量有界；写盘失败零状态发布；撤销持久阻断且不回退MQTT，旧成功决定不复活绑定 |
| TV-A12 | 配置迁移与应用发现 | 核心初始配置不改；宿主完整config摘要变化后旧路由休眠，明确绑定后才执行；旧探测/缓存不跨绑定；发现不授权，过期列表不冒充新鲜，未授权应用零调用 |
| TV-A13 | 显式动作组合 | 相同逻辑模型与当前原生会话；声明覆盖所选native_paths，拒绝缺失/重复/陌生能力及不完整分区；未选能力不取得执行权。跨端FIFO、单路径离线、撤销及重启均无回退/补发；分别核对协议夹具与实际Agent |

TV-A01至TV-A08及TV-A10至TV-A13覆盖基础接入目标；未发布能力保持不可用。TV-A09属后续扩展；ADB连接与只读信息获取不计控制验收通过。

TV2a 基础动作与 TV2b 属性分别记录，基础按键通过不代表音量/静音或完整电视模型通过。适配器先以假进程验证固定目标、参数白名单、应用发现/撤销、超时、输出上限、退出和进程中断，再以真实网关与网页验证原操作恢复；Broker 故障仅阻断依赖它的路径。故障夹具须能区分“未调用执行端”“已调用但结果未知”和“输入已提交”，不能只看最终 HTTP 状态码。

静态 ADB 路由的模型负例至少包含非空必填输出、非对象输出、允许额外字段的输出和 `completion=observed`；换绑应在提交前拒绝，原绑定与命令历史保持一致，随后不得触发业务调用。输出/completion已有首次绑定、真实签名换绑和恢复负例；允许额外字段的模型本身也须被共享模型校验拒绝。完整路径/输入负例还应包含陌生键、输入扩大及语义/risk/idempotent变化，并有合法输入子集正例；当前专项覆盖及缺口只在24维护。

绑定恢复至少破坏一条动作路由、模型属性/事件及原决定result与request的对应关系，验证拒绝且不改写快照；不得因残缺路由让某个动作回退MQTT。接口需核对摘要语法、重复/额外字段和有界输入。换绑与OTA占用、dispatched并发分别验证；撤销后迟到结果只能归原命令。新增浏览器旅程应证明本地原记录失败零POST、丢响应后刷新只查原键、390px布局、发现/授权区别、撤销重启与配置迁移，并在模拟副作用前由独立只读SQLite连接确认绑定和dispatched均已提交。

组合另覆盖能力声明超集的正例、旧会话拒绝、恢复后重新证明能力、两种方向的跨端FIFO，以及native/adapter来源不能互换。快照v6→v7在隔离库验证，v6隐藏native_paths/compose、坏分区和未来版本须拒绝且不改写。网页逐动作availability与原生应用不显示ADB授权分别检查；创建组合当前通过CLI，不将网页状态/撤销检查写成创建表单通过。Agent本机迁移须保留旧模型完整原包、confirmed/unknown/未决及high_watermark，覆盖迁移提交前后失败、旧最终结果回收与反向拒绝；Android须证明材料/日志原子回滚、坏日志零替换及授权保留。已有网关Device跨模型绑定、真实JVM组合、Android端上和物理归属分别验收，不能由本机迁移检查相互替代。

上述4.13证据保留历史范围。遥控配置日志v3与旧应用模型记录共存的实现由 [设备合同](../contracts/tv-agent.md) 维护，当前核心/宿主阶段结果及真实JVM组合失败见 [24第4.15节](24-实施计划与进度.md#415-tv-agent模型配置与日志迁移文档同步)。最终复验须在最后源码修改后执行；不把阶段APK/lint或静态文档检查提升为最终软件通过。

## 7. 可选音频播放终端专项验收

以下为 FR-33 / UC-24 的验收计划，实际结果统一见 [24](24-实施计划与进度.md)、[30](30-设备支持矩阵与证据台账.md)，接入设计见 [36](36-音频播放终端与DLNA接入.md)。独立桌面播放实验不替代平台接入验收。

| 编号 | 范围 | 必须取得的证据 |
| --- | --- | --- |
| AUDIO-A01 | 发现与绑定 | 用户批准精确目标；区分身份线索与认证保证；地址变化重新核对；拒绝未授权设备/媒体引用 |
| AUDIO-A02 | 播放与状态 | 统一入口发送有限音频；分别记录 SOAP 结果、HTTP 拉取、设备状态与实际听感；停止、自然结束和延迟单独验证 |
| AUDIO-A03 | 音量与格式 | 使用保守音量与用户上限；读写回验；开启/取消静音分别验证；记录测试编码、采样率、声道和长度，不外推格式/流式支持 |
| AUDIO-A04 | 失联与未知 | 覆盖媒体不可达、响应丢失、设备/网关重启；保留原操作，不盲目重播，不恢复过期播报，不将失联当作声音已停止 |
| AUDIO-A05 | 取消与原厂共存 | 取消、换人、迟到 TTS 均不启动旧播放；原厂唤醒/其他控制端抢占时不自动抢回；核对结束平台会话后原厂入口可用性 |
| AUDIO-A06 | 可选语音闭环 | 外部麦克风→ASR→实际 AI→TTS→DLNA 真机可听；半双工避免回复自激；单独报告远场、回声消除和打断是否验证 |
| AUDIO-A07 | 媒体访问与保留 | 音箱所在网络可达；短时引用、GET/Range、类型和过期/清理有效；URL/日志无模型密钥和平台凭据，明确普通 HTTP 的可见范围 |

播放终端的基础验收不要求 AUDIO-A06；只有可选语音闭环通过后才宣称能通过 LimeIoT 对话。原机麦克风接管、默认语音后端切换和全双工不由上述播放验收覆盖。
