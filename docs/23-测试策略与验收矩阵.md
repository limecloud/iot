## 2. 功能验收追踪

定时受理与已有命令出队独立提交：追加容量故障检查，旧运行占满1024条时，定时返回capacity_exceeded且原游标未改变，已经受理的设备命令仍能耐久转为dispatched并返回原Envelope。此检查不能代替设备回执；实际MQTT/动作/unknown回归另行运行。

每周定时使用`npm run test:rules:schedules`：固定时间覆盖严格形状/时区/星期、UTC与本地日期、DST缺失/重复、半小时变化、整日跳过、回拨、部署后基线、间断及离线不补发、条件/离线目标与原证据；Store覆盖游标/运行/命令/事件原子提交、v11恢复、v1–10隐藏新字段零改写和亚秒无重复写盘。独立真实墙钟旅程经CLI校验/预演、任务显式commit、MQTT模拟灯执行1次与重启不重放。Web检查创建/回填/修改/取消/停用、星期/时区输入、预演失效及390px；真实PTY检查时间拒绝重填、修改与取消、毫秒冷却及原任务。`npm run test:rules:schedules:native`检查Swift/Kotlin宿主合同与真实网关零命令预演、创建/修改/停用。Android APK/lint、SwiftUI语法和原生完整运行分别登记；软件结果不代替实机。

条件使用`npm run test:rules:conditions`，覆盖比较类型/单位、AND/all/any、4层与32节点、非确认/过期/未来/缺失/离线、未满足不占冷却、预演零副作用、原证据冻结、换模保护及AI草案不扩权。SQLite覆盖未满足/受理两类提交失败，v9夹带新条件或证据、v10坏证据均拒绝零改写，旧v9空条件可升级。MQTT/HTTP/CLI旅程核对3条明确手动命令、1条自动化命令、2次条件未满足，以及重启后的原条件观测不变。

### 5.1 身份到期与执行链路的分层验收

原生设备按下表分别取证；采用厂商接口、无证书广播或单向控制的适配器，按其实际认证和执行机制验证，不伪造同等身份能力。本节定义验收要求，当前结果统一见 [24](24-实施计划与进度.md)。

| 验证面 | 必须取得的证据 | 结果适用范围 |
| --- | --- | --- |
| 身份维护 | 原证书、固定CA、公钥、恢复用途和原CSR核对；耐久提交故障及重开恢复 | 对应身份/存储实现；不能代替连接后的执行保护 |
| 有效窗口 | 真实证书解析，叶证书与CA分别实际到期，可信时钟失效后锁定 | 日期与资格模块；不能代替任务、队列或驱动运行 |
| 目标构建 | 精确SDK/配置、日期校验启用、实际镜像与槽容量 | 固定目标可构建；不能代替MQTT运行或Flash效果 |
| 运行期软件集成 | 生产适配器、核心、工作任务、事件与队列共同运行，跨到期核对实际宿主副作用 | 明示的平台替代层与软件链路；不能代替芯片、系统权限或实机 |
| 目标系统与实机 | 实际系统身份设施、驱动、网络、供电故障及更新恢复 | 精确型号/固件/配置；不能扩展到其他设备 |

C3运行期软件验收须运行生产 `espidf.c` 与实际C核心。宿主可替代FreeRTOS、MQTT和NVS等平台设施，但必须记录替代范围；单独调用窗口、复刻worker逻辑，或仅运行另一份宿主MQTT驱动均不能覆盖此项。具体门槛为：

1. 有效期内完成真实mTLS连接与至少一次宿主驱动效果；分别使用短期叶证书、短期CA跨过真实到期时刻，不修改系统时间或关闭日期校验。
2. 到期前已入队、到期后待消费的请求自身期限仍有效；到期后接收、消费、实际驱动提交、发布与OTA会话门禁逐项核对，新增驱动效果为零。OTA平台夹具的调用计数只证明相应门禁，不等于真实下载、写入或安装通过。
3. 核对ready失效、旧连接代次与迟到事件被拒绝、MQTT停止和失效后不再重连；有效期内的断线按既有5秒重连政策验证。可信时间恢复不能解锁已失效实例。
4. 保留原命令及OTA日志、已确认/失败/unknown与未决尝试；重开或新凭据恢复后先查原操作，旧动作不重放。故障证据与对应源码摘要一起冻结，不能将目标构建或另一终端的通过结果迁移到本项。

TV的宿主到期旅程、C3身份维护及C3窗口专项各有独立证据，见 [24第4.33节](24-实施计划与进度.md#433-tv过期身份维护与持续有效期软件闭环)、[第4.34节](24-实施计划与进度.md#434-c3过期身份维护与原csr恢复) 与 [运行期阶段](24-实施计划与进度.md#c3运行期身份有效窗口)。C3生产适配器宿主集成已新增3条通过旅程，覆盖真实mTLS、叶证书/CA到期、时钟失效、分片/队列、受控重连和各门禁；具体平台替代范围见[集成记录](24-实施计划与进度.md#c3适配器运行期软件集成)。OTA任务日志及换证后重开不由此提升，完整ESP MQTT/FreeRTOS和Android端上仍单列；实机按用户要求跳过。

### 5.2 换证后新进程与已有执行记录的连续性

| 验证面 | 必须取得的证据 |
| --- | --- |
| 维护前基线 | 在有效旧身份下经生产核心形成confirmed、failed与未决intent等记录；保存原ID、Envelope或合同要求的原请求指纹、结果及持久文件。核对实际宿主副作用次数 |

| 原OTA连续性 | 经生产日志API形成未决任务后重开，保留完整安装Envelope、执行ID、摘要与基线；恢复标记生效，安装推进拒绝、占用保留、查询零安装。终态只随合同要求的本机证据收敛，不由换证、重连或缺记录推定完成 |

### 5.3 OTA日志跨恢复提交故障矩阵

本节的独立软件矩阵已由`npm run test:firmware:ota-recovery`执行，结果见 [24第4.42节](24-实施计划与进度.md#442-ota日志跨身份维护与进程恢复的提交故障)。沿第5.2节取得同轮同设备维护身份，用生产日志 API 形成每个合法前置状态，再分别注入“提交前返回失败”和“快照已耐久提交后返回失败”；不用手工拼接日志 JSON 代替正常状态生成。下表前4个提交点及rejected/failed/succeeded/rolled_back四种终态共8点、16项，分4组通过。原有12项启动拒绝及4项控制回执提交故障仍分别保留。

| 提交点 | 注入前的合法状态 | 重开后的核对重点 |
| --- | --- | --- |
| `prepare` 保存原安装意图 | 无冲突未决任务，完整原Envelope与基线已核对 | 区分未保存与已保存的原意图；不根据缺记录自动重发，已恢复意图保持占用 |
| `advance` 到 `installing` | 本次运行的 `intent` | 实际耐久状态为 `intent` 或 `installing`；均标记恢复，不能继续安装 |
| `advance` 到 `awaiting_boot` | 本次运行的 `installing` | 实际耐久状态为 `installing` 或 `awaiting_boot`；不重复暂存、选择启动或重启 |
| `bind_boot` 保存本机启动绑定 | 本次运行的 `awaiting_boot`，且尚无绑定 | 核对绑定究竟是否保存；缺绑定不补造，已有绑定仍需独立启动观察支持 |
| `finish` 保存各可达终态 | 分别满足拒绝、失败、成功或回滚的状态与本机证据条件 | 失败前对象不发布终态；重开区分原未决与已保存终态，按消费者证据门槛报告，不改写原结果 |

每个场景分别保存失败前、错误返回后和进程重开的身份/回执/OTA持久摘要，以及存储尝试、下载、暂存、启动选择、重启和控制驱动计数。当前故障对象的合法查询/变更须返回存储错误并保持占用；重复原请求、不同新请求和重连不增加写入或副作用。重开后，已耐久保存的原Envelope、执行ID、摘要、基线与绑定保持连续；原查询零新增安装，未决继续阻止冲突控制。终态确已保存时，报告资格与占用恢复分别按日志和消费者合同核对，解除占用不能单独证明安装成功。

故障副本独立运行，明确记录是否同时重开设备和网关 SQLite，避免把网关原 FIFO 占用误判为端侧未接收。宿主 NVS、运行基线、安装及启动端口可以是显式夹具，必须分项标明；日志恢复通过不等于真实镜像安装、启动健康或芯片掉电通过。MQTT原查询的断言还须覆盖不支持发布终态时保持未知，不以无结果伪装成功。生产行为边界见 [13第9.2节](13-OTA与制品交付规范.md#92-设备日志提交失败的恢复语义)，执行结果与故障证据只在24登记。

当前实现先串行运行身份/控制恢复2条、未决OTA恢复1条，再执行4组矩阵；每条60秒、每进程120秒的期限保持。矩阵逐例重开设备，不重开网关SQLite；直接MQTT下行覆盖原安装、不同新安装、原查询、冲突控制及旧会话，每次等待worker队列为0后核对写入与副作用。故障对象保持占用；重开后的未决继续阻止控制，无记录或已保存终态时只有明确HTTP新命令产生1次效果。安装暂存、启动选择、重启和OTA结果发布计数均为0：当前基线不可用，终态仅为生产API构造的显式夹具，不能据此宣称安装或健康结果通过。原始失败、原子文件交接修复及受测摘要由4.42归档。

### 5.4 OTA传输期间的凭据保护

入口为`npm run test:firmware:ota-credentials`，依赖固定ESP-IDF SDK及已构建的宿主密码库。生产传输与凭据窗口直接组合，未复制传输或证书有效期算法；实际传输为本地HTTPS，文件端口在失效时仅记录调用，不额外拦截I/O，拒绝必须由生产guard触发。

| 场景 | 注入/跨期位置 | 核对重点 |
| --- | --- | --- |
| 有效凭据正例1项 | 全部下载与备用内容回读 | 262,145字节与Node摘要一致，实际文件/长度/权限正确，窗口仍可用 |
| 叶证书到期2项 | HTTPS首次读取返回前、备用内容回读首块返回前 | 启动仍有效；真实墙钟跨期后停止，无新增I/O、摘要或验证证明 |
| CA到期2项 | 同上 | 叶证书仍有效、下载CA独立；HTTPS仍连接不绕过设备资格 |
| 可信时钟失效4项 | 首次I/O前、读取返回前、写入返回前、回读返回前 | 先前内容按实际计数保留；恢复时钟不解锁当前窗口，原对象重试零新HTTPS请求 |

9项软件结果见 [24第4.43节](24-实施计划与进度.md#443-ota传输期间凭据失效的软件验证)。失败均为`ota_transfer_authorization_lost`，关闭已打开的来源，已开始暂存时调用abort；部分文件或完整文件均保留真实字节，未完成回读时不产生验证证明。证书到期后显式新开窗口也拒绝；时钟恢复后新开可以重新验证身份，但测试不据此续传或批准安装。源、依赖和宿主二进制摘要由入口冻结，`--build-only`只构建。

本专项不启动Broker/网关、生产安装消费者或worker，不创建/恢复升级日志，也不选择启动或重启；不能继承5.3的身份维护/NVS证据，5.3也不能继承本专项的HTTPS证据。完整提供方失权、awaiting_boot之后的未知恢复、实际ESP系统和芯片分别验收。

静态 ADB 路由的模型负例至少包含非空必填输出、非对象输出、允许额外字段的输出和 `completion=observed`；换绑应在提交前拒绝，原绑定与命令历史保持一致，随后不得触发业务调用。输出/completion已有首次绑定、真实签名换绑和恢复负例；允许额外字段的模型本身也须被共享模型校验拒绝。完整路径/输入负例还应包含陌生键、输入扩大及语义/risk/idempotent变化，并有合法输入子集正例；当前专项覆盖及缺口只在24维护。

绑定恢复至少破坏一条动作路由、模型属性/事件及原决定result与request的对应关系，验证拒绝且不改写快照；不得因残缺路由让某个动作回退MQTT。接口需核对摘要语法、重复/额外字段和有界输入。换绑与OTA占用、dispatched并发分别验证；撤销后迟到结果只能归原命令。新增浏览器旅程应证明本地原记录失败零POST、丢响应后刷新只查原键、390px布局、发现/授权区别、撤销重启与配置迁移，并在模拟副作用前由独立只读SQLite连接确认绑定和dispatched均已提交。

组合另覆盖能力声明超集的正例、旧会话拒绝、恢复后重新证明能力、两种方向的跨端FIFO，以及native/adapter来源不能互换。快照v6→v7在隔离库验证，v6隐藏native_paths/compose、坏分区和未来版本须拒绝且不改写。网页逐动作availability与原生应用不显示ADB授权分别检查；创建组合当前通过CLI，不将网页状态/撤销检查写成创建表单通过。Agent本机迁移须保留旧模型完整原包、confirmed/unknown/未决及high_watermark，覆盖迁移提交前后失败、旧最终结果回收与反向拒绝；Android须证明材料/日志原子回滚、坏日志零替换及授权保留。已有网关Device跨模型绑定、真实JVM组合、Android端上和物理归属分别验收，不能由本机迁移检查相互替代。

TV-A14新增门槛为快照v7→v8迁移、旧安装来源兼容及v8内置来源重启恢复；v1–7隐藏新动作/绑定/结果、未知未来版本和被篡改来源须拒绝且零改写，提交失败零内存/事件发布。共享协议、CLI与网页分别验证来源和完整原结果、保存失败零POST、丢响应/404只GET，以及更换换绑动作类型不能绕开未决记录。独立JVM旅程从已有应用模型设备开始，经明确网关换绑、本机材料/日志迁移、新会话及网关/JVM重启，核对confirmed/unknown、旧完整Envelope和序号连续；不以预置遥控模型或修改config_hash代替迁移。以上为验收要求；领域、恢复、网页及独立JVM已有软件结果，实际Agent/ADB组合、Android端上及物理归属仍单列，见 [24第4.19节](24-实施计划与进度.md#419-内置模型绑定与跨模型软件闭环)。
