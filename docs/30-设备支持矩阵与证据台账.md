## 2. 单型号档案

必须登记硬件身份、采购与批次、照片/接口引用、固件和依赖、映射修订、能力、身份保证、供电、原始样本受控引用、验证步骤、结果、未知项和维护责任。

接入记录需包含原生/标准协议/公开接口/厂商合作/专项研究路线，本地或云路径，OS/SDK、接口与许可来源，当前获准主体、用途与操作，资格/认证的适用版本和核对日期。敏感协议、凭据或合同只保留受控引用。资料不足时分别说明技术、权限或商业交付缺口。

每能力分别记录 discovered/read/control/notify/reconnect/recover/update（适用时）。不支持项说明原因，未测项为not_run；单向发射只能证明sent_only，不能给出不存在的执行确认。

## 3. 支持阶段

候选 → 资料核对 → 样本/回放 → 实机验证 → 独立复现 → 套件交付。每次提升需具备对应证据，旧固件通过不自动涵盖新固件。安全或严重兼容问题可暂停支持，同时保留影响版本和恢复说明。

技术验证与用途/资格状态分别记录；套件交付需同时满足目标能力证据和该用途的有效条件。固件、接口、地区或条款变化时标记受影响范围待复验，接口停服或授权撤销时暂停相关能力并给出原因；平台其他设备继续按各自证据运行。

## 4. 生态与组合

生态连接额外记录方向、地区、账号资格、控制器型号/系统、Fabric或连接身份、支持类型与认证，级别见 [31](31-多生态兼容与开放接入.md)。

组合包记录精确模块版本、机械/电气约束、模型依赖、内容、资源和允许环境。各模块单独通过不代表任意组合通过；飞行和机器人等按实际组合验证。

## 5. 证据索引

每份证据包含用例/需求、固定源与制品、步骤、观察时间、操作引用、预期与实际、失败/跳过及摘要。敏感证书、Token、私有媒体和原始客户数据不进入公开表。

当前登记3份摘要：电视只读观察、小度DLNA播放及电视网页/网关ADB有限控制实验，见下方对应条目；其他型号和未测能力不由此提升。实现后更新此处和 [24](24-实施计划与进度.md)，不从设计示例、模拟数据或外部项目的支持清单导入虚假完成状态。

## 7. DEV-CAND-09 小度音箱播放实验

记录：`EVID-SPEAKER-20261102-01`，观察日期2026-11-02；[脱敏摘要](evidence/2026-11-02-xiaodu-dlna-playback.json)。接入方向为用户自有音箱作为可选播放终端，路径为获准的局域网 UPnP AV / DLNA 控制与音箱主动拉取 HTTP 音频；实验由独立电脑工具执行，未经过 LimeIoT 网关。

| 项目 | 观察事实与边界 |
| --- | --- |
| 身份 | UPnP manufacturer 为 DuerOS、modelName 为 DuerOS-Render，modelNumber 为空；App 报告固件 2.30.18.2026041017。用户确认圆形 DC 供电、开壳与[首代拆解参考](https://www.52audio.com/archives/6004.html)相符；精确型号、芯片及 PCB 修订未独立读取 |

| read | GetVolume、GetMute、GetTransportInfo 成功；GetProtocolInfo 成功但 Source/Sink 为空，不能据此建立格式兼容清单 |
| control：播放 | SetAVTransportURI、Play 返回 HTTP 200；音箱以 GET/206 拉取局域网 WAV，GetTransportInfo 报告 PLAYING；最大音量测试后用户明确回复“听到了” |
| control：音量/停止/静音 | 按用户要求将音量从1设为100并成功读回；Stop、取消静音请求返回 HTTP 200。物理停止、自然播放结束、开启静音的效果未独立验证；100不作为默认设置 |

原始本地发现、只读、提示音和最大音量实验记录的 SHA-256 收录于脱敏摘要；原始记录受控保留，不公开设备网络身份、媒体地址、宿主路径或凭据。本文编写未重新操作音箱。当前维护范围为单样本实验，后续适配须指定维护人；可选终端设计与验收入口为 [36](36-音频播放终端与DLNA接入.md)、[23](23-测试策略与验收矩阵.md)，平台进度仍由 [24](24-实施计划与进度.md) 维护。
