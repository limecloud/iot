# 自研物模型规范

更新日期：2026-11-02。本文描述设计基线；当前 0.1 已实现子集及校验边界见[正式校验合同](../contracts/model-validation.md)。机器可读设计示例见 [examples](examples/README.md)，适配规则见 [07](07-异构协议与适配器规范.md)。

## 1. 模型层次

模型按产品模型 → 服务实例 → 属性、动作、事件组织。模型是产品能力定义，设备是绑定某个模型发布版本的实际实例；家庭、房间和用户名称不写进公共产品模型。

| 对象 | 职责 | 示例 |
| --- | --- | --- |
| Model | 产品的完整能力组合 | `urn:limeiot:model:demo-lamp:1` |
| Service | 内聚能力语义与实例 | 语义 `urn:limeiot:service:light:1`，实例 `light` |
| Property | 可读取、写入或通知的状态 | `light.power`、`light.brightness` |
| Action | 有输入输出与副作用的操作 | 校准、开始测量 |
| Event | 已发生的离散事实 | `button.pressed` |

标准语义归平台模型目录管理；第三方采用自己的发布者命名空间，例如 `urn:example-vendor:service:air-quality:1`。语义标识、设备型号和公共模型资料互相关联，但不能互相替代。

## 2. 标识和版本

`id` 为稳定 ASCII 小写机器标识，建议匹配 `[a-z][a-z0-9_-]{0,63}`。属性路径为 `service_id.property_id`，不包含本地化名称、数组索引或协议地址。

模型包含 `schema_version`、`model_id`、`model_version`、`services`。`model_version` 采用三段语义版本；`model_revision` 为规范模型投影按 RFC 8785 JCS 规范化后的 SHA-256 摘要，存放在引用方，不在被摘要正文中自引用。当前校验器只生成候选修订，与输入正文的 `document_digest` 分开；候选修订不代表已发布或已安装。

字段删除、类型变化、单位变化、写入含义变化均为破坏性变更；增加可选能力也必须经兼容性检查，不能仅根据版本号放行。语义主版本变更使用新标识。发布正文不可覆盖，设备升级必须明确切换模型绑定。

当前已实现[定义兼容性检查](../contracts/model-compatibility.md)：旧命令/动作输入必须仍可接受，新上报、事件及动作输出必须仍可被旧读取者解析；读写属性同时满足两种方向。已有服务、属性、动作、事件不能删除；语义、单位、保鲜期及动作的幂等性、风险和完成范围不能改变。有限对象子字段按输入/输出方向检查，不等同顶层能力删除。该报告不证明命名空间所有权或真实设备支持。

## 3. 属性定义

| 字段 | 规则 |
| --- | --- |
| `id` / `semantic_id` | 实例内唯一；标准语义可复用 |
| `schema` | JSON Schema 2020-12 的受限子集 |
| `access` | `read`、`write`、`notify` 的非空集合 |
| `unit` | 稳定单位代码，显示本地化另行投影 |
| `max_age_ms` | 观测保鲜期；当前0.1必填，范围为1到2^53-1毫秒 |
| `extensions` | 后续设计中的有命名空间扩展，不能覆盖标准字段；当前0.1拒绝该字段 |

首批类型：boolean、integer、number、string、有限 object；支持 enum、minimum、maximum、长度与 required。integer 限制在跨语言精确范围内，number 必须有限，禁止 NaN/Infinity；时间和二进制采用有格式约束的字符串。固件仅实现实际需要的受限校验，禁止在 MCU 嵌入任意 Schema 解释器。

温度使用摄氏度等明确单位，精度、缩放和协议原始整数在适配器转换。枚举以稳定机器码表示；未知厂商值保留原始证据并标 unknown，不映射为最接近的已知值。

## 4. 动作和事件

Schema 2 的动作必填 `id`、`semantic_id`、`input`、`output`、`idempotent`、`risk`、`completion`。risk 限于 low/medium/high，completion 限于 submitted/observed；输入和输出复用属性的受限 Schema。Schema 1 继续要求 actions 为空。取消与长任务尚未进入此动作定义，不能提交设计字段；具体规则见[正式校验合同](../contracts/model-validation.md)。

设置 `power=true` 与 `toggle` 具有不同副作用与幂等语义。当前不根据 idempotent 标记自动重发，未知结果仍查询原操作；risk 也不替代当前授权。

事件定义数据 Schema、事件身份和去重窗口。按键事件是离散事实，不能以 retained 状态补发，也不能由温度属性变化猜测不存在的事件。

原子多属性写入必须由能力明确声明；否则平台按逐项命令返回部分结果，不承诺跨属性或跨设备事务。

### 4.1 电视属性与遥控动作

电视音量、静音属于状态属性；按键和启动应用属于动作，不能用可写属性模拟一次性输入。[电视模型](../contracts/models/android-tv.json) 已定义 `remote.press`、`apps.launch`、`audio.volume` 与 `audio.muted`；调用使用 `action.invoke`，参数置于 operation.value。正式输入、证据与顺序恢复规则见[命令合同](../contracts/commands.md)。

submitted 只确认输入提交，不能显示为目标界面已达成；observed 须有模型要求的观测依据。模型定义通过不证明具体电视支持，型号与路径边界见 [34](34-电视终端与AndroidTV接入.md)，实施状态见 [24](24-实施计划与进度.md)。

## 5. 运行时能力

设备握手声明精确模型修订和可用能力。适配器可映射模型子集；不支持、只读、需连接、需密钥等限制作为能力描述返回。开发者定义了某属性，不代表该型号或当前固件已实现它。

以上能力子集为接入设计要求。当前正式模型没有设备级可选能力协商字段，核心仍要求完整属性快照；实际能力组合不同时，应绑定与其一致的精确模型，并完成对应消费者验证。不能直接绑定完整电视模型后填零/false 冒充缺失的音量、静音观测；动态能力协商另行演进正式合同。

观测携带来源、时间、质量与序列；定义和当前值分开。状态质量采用 `confirmed`、`estimated`、`stale`、`unknown`，表示观测可信程度，不等同于命令结果。

## 6. 展示与工具投影

名称、说明和枚举显示文本通过模型资料资源提供，语义与标识不随语言变化。UI 控件提示只能影响显示，不能增加写权限或放宽值约束。

工具目录从物模型和正式用例生成；可写属性不自动对所有 Agent 开放。WoT/Matter/HA 的模型投影是适配输出，核心模型保持独立。

## 7. 验收

发布前验证唯一标识、引用、范围、样例、兼容性和所有当前语言；Rust、Go、TypeScript、C 绑定通过同一正负测试向量。绑定变化、设备模型不匹配、非法单位、未知枚举和越界写入必须得到稳定错误。

## 8. 扩展能力

机器人任务、音频交互、视觉媒体和安全停止通过内聚服务扩展；长任务引用独立Task，媒体属性保存受控引用。物理模块能力与模型服务能力共享发现语义，但输入输出、实时性、资源、身份保证和调用权限分别声明。组合与场景合同见 [32](32-能力组合与场景应用.md)。
