## 2. 为什么不直接以其他项目为内核

采用HA、ESPHome或zigbee2mqtt作为必需运行内核可以更快获得部分功能，但会将平台模型、固件和设备适配演进绑定到其内部合同。当前选择学习经验、合规复用独立基础能力，并将互操作放在适配层。

自研必须以纵向切片逐步证明价值，避免为了“自主”重写TLS、标准MQTT或成熟密码算法。若无法证明开发效率和交付收益，应缩小实现范围或替换独立组件，而非扩大内核。

小米是模型与产品工程的重要参考，异构接入同时参考 HA/openHAB 等，依据见 [35](35-多品牌设备接入与升级架构调研.md)。公开资料不足以判断小米/华为整体复杂度，更不能把厂商 UI 插件当作网关协议驱动。公开源码优先阅读，具体包或运行机制的疑问再用 REA 核实；单个客户端或电视样本不能证明整个厂商平台实现。

### 2.1 基础依赖受到限制时的处理

先识别具体阻塞来自源码许可、硬件/BSP、运行能力还是商业生态。选择满足要求的现有组件并隔离接口；具体缺口按替换组件或硬件、升级版本、维护必要分支、局部自研的成本和维护能力决定。适配层可以约束依赖范围，但不能消除芯片指令集、资源与实时行为差异，跨平台仍需验证。

| 限制 | 优先处理 | 自研范围的判断 |
| --- | --- | --- |
| 许可或商业用途不满足 | 核对具体组件，选择符合用途的替代、板卡或正式授权 | 只有缺少可用替代且确有产品价值时，评估独立实现相应组件 |
| 驱动/API或功能缺口 | 使用公开扩展点、适配器或可维护的上游补丁/分支 | 以复现缺陷与明确合同为依据，限定到驱动、绑定或必要模块 |
| 二进制组件无法自行修复 | 核对原厂维护、版本和替代硬件，记录替换成本 | 重写OS不能自动获得无线/芯片源码，需先解决实际硬件与驱动条件 |
| 厂商云、生态或认证受限 | 保持原生主链，选择标准接口或推进合作 | 自研OS不能产生第三方服务访问权或认证资格 |
| 自有品牌需求 | 按许可维护归属，产品使用自有品牌 | 不因品牌定制扩展到OS研发 |

完整OS自研需要独立的产品必要性、替代方案比较、硬件条件、团队预算和长期维护评估，当前范围保持在既有OS/框架之上的IoT平台。平台自主性通过自有模型与应用协议、身份/签名/升级控制权、可复现制品和明确替换路径实现；已部署基础能力的运行依赖须经离线测试证明。

## 3. 风险与处理

| ID | 风险 | 触发信号 | 应对 |
| --- | --- | --- | --- |
| R1 | 自研维护面过宽 | 主链长期无法实机闭环 | 固定三类样板，延后型号扩张 |
| R2 | AI差异化不足 | 仅自然语言入口，接入效率未改善 | 测量Agent任务、适配复现与交付收益 |
| R3 | 型号/供应链漂移 | 相同料号不同PCB/固件 | 冻结BOM、批次与变更复验 |
| R4 | 封闭生态资格 | 只有网页壳、专用客户端权限或未知用途条款 | 选型阶段核对路径与资格；原生主链独立，生态按实际条件交付 |
| R5 | 状态或副作用错误 | 发送即成功、未知自动重试 | 原操作、证据、状态机和故障注入 |
| R6 | 多模态费用和数据失控 | 无界上下文、静默外发/重试 | 路由政策、预算、用途授权和媒体引用 |
| R7 | 机器人/玩具组合风险 | 物理不兼容或无本地停止 | 模块约束、限制动作、受控实测 |
| R8 | 许可/权利不清 | 模型、角色或代码来源未知 | 固定来源、依赖审核和制品清单 |
| R9 | 社区适配不可维护 | 只有一次成功样本，接口或固件变化后缺乏复验 | 独立验证、维护责任、型号矩阵与变更复验；失效能力暂停支持 |
| R10 | 备份与升级失真 | 回退程序但Schema/密钥不可恢复 | 发布兼容矩阵及真实恢复演练 |
| R11 | NAS或云网络假设不成立 | ARM镜像可构建但未实测、云长连接中断、离线页面缺资源 | 架构/型号分验，页面本地打包，游标重连；SQLite使用NAS本机卷 |
| R12 | 验收证据与当前源码脱节 | 报告之后源码变化，仍把旧截图或通过结果用于当前版本 | 固定源码与证据摘要；保留历史结果，对变化涉及的旅程重新验收，当前复核见 [24 第4.8节](24-实施计划与进度.md#48-文档复核与后续交付门槛) |
| R13 | 回执容量耗尽或恢复边界倒退 | 未确认/未知记录占满128条/1MiB、网关原账本达到4096条；两端同时恢复旧备份 | 已确认最终结果按正式合同回收，high_watermark及未知记录保留；满容量继续拒绝，不删库或换身份解锁。网关账本归档与独立恢复依据仍须单独设计，端上与升级连续性另验；见 [34 第5.4节](34-电视终端与AndroidTV接入.md#54-耐久回执容量与安全回收的设计门槛) |

## 4. 实施前必须测定的参数

目标工具链版本、首款板卡与NCP固件、设备报文/资源上限、各模型的硬件与延迟、长任务停止行为、第一组生态控制器、具体厂商合作接口与正式套件BOM。它们需要技术验证和采购数据，不靠架构文档预设为事实。

## 5. 决策更新

变更记录决定、原因、影响合同、消费者、迁移和验收。现行规范直接同步到唯一事实位置；无已发布消费者时不增加过渡别名与长期双轨，避免形成多套产品语义。
