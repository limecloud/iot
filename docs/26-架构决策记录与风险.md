更新日期：2026-11-01。状态：当前设计决定；实现状态见 [24](24-实施计划与进度.md)。本文件记录现行取舍，不保存讨论流水。

## 1. 架构决定

| ID | 决定 | 原因与代价 |
| --- | --- | --- |
| ADR-01 | AI-first，合同与工具先行 | Agent可发现、执行和验证；需建设机器语义和证据链 |
| ADR-02 | 核心采用通用Space，家庭/玩具首批 | 向教室、企业、健身扩展；场景政策须独立验证 |
| ADR-03 | 自研物模型和MQTT应用报文 | 控制语义与演进；需长期维护协议与迁移 |
| ADR-04 | 自研Rust网关、事件总线、状态和DSL | 本地自治与依赖独立；承担内核维护成本 |
| ADR-05 | ESP-IDF原生SDK | 复用芯片与标准基础，业务核心自主；无线组件不是全部开放 |
| ADR-06 | 所有外部业务组件经Port/Adapter | 替换与故障隔离；需保持接口小而具体 |
| ADR-07 | SQLite与Outbox，不预建分布式MQ | 降低本地运维成本；单节点规模与写入需测量 |
| ADR-08 | 一个主网关服务一个空间起步 | 控制执行权清晰；多主能力后续单独设计 |
| ADR-09 | 平台模型/媒体服务，提供方独立 | 多模态可组合，Ollama可替换；资源、数据和预算需治理 |
| ADR-10 | 命令、长任务、会话分层 | 支持机器人与多模态；不得混淆取消和完成 |
| ADR-11 | 共享业务用例，GUI/TUI/CLI/MCP多端投影 | 交互同义与当前授权；宿主逐项验收 |
| ADR-12 | 多生态双向分级兼容 | 保留用户已有入口；资格、型号、地区与认证成本显式 |
| ADR-13 | 原创项目采用Apache-2.0 | 开放商业使用与贡献专利条款；依赖保持原许可 |
| ADR-14 | 组合包先审核后扩大分发 | 支撑开发者和商家创新；不提前建设通用市场和不可信运行平台 |

## 2. 为什么不直接以其他项目为内核

采用HA、ESPHome或zigbee2mqtt作为必需运行内核可以更快获得部分功能，但会将平台模型、固件和设备适配演进绑定到其内部合同。当前选择学习经验、合规复用独立基础能力，并将互操作放在适配层。

自研必须以纵向切片逐步证明价值，避免为了“自主”重写TLS、标准MQTT或成熟密码算法。若无法证明开发效率和交付收益，应缩小实现范围或替换独立组件，而非扩大内核。

## 3. 风险与处理

| ID | 风险 | 触发信号 | 应对 |
| --- | --- | --- | --- |
| R1 | 自研维护面过宽 | 主链长期无法实机闭环 | 固定三类样板，延后型号扩张 |
| R2 | AI差异化不足 | 仅自然语言入口，接入效率未改善 | 测量Agent任务、适配复现与交付收益 |
| R3 | 型号/供应链漂移 | 相同料号不同PCB/固件 | 冻结BOM、批次与变更复验 |
| R4 | 封闭生态资格 | 只有网页壳或专用客户端权限 | 完成官方资格验证，保持独立路线 |
| R5 | 状态或副作用错误 | 发送即成功、未知自动重试 | 原操作、证据、状态机和故障注入 |
| R6 | 多模态费用和数据失控 | 无界上下文、静默外发/重试 | 路由政策、预算、用途授权和媒体引用 |
| R7 | 机器人/玩具组合风险 | 物理不兼容或无本地停止 | 模块约束、限制动作、受控实测 |
| R8 | 许可/权利不清 | 模型、角色或代码来源未知 | 固定来源、依赖审核和制品清单 |
| R9 | 社区适配不可维护 | 只有一次成功样本 | 独立验证、维护责任与型号矩阵 |
| R10 | 备份与升级失真 | 回退程序但Schema/密钥不可恢复 | 发布兼容矩阵及真实恢复演练 |

## 4. 实施前必须测定的参数

目标工具链版本、首款板卡与NCP固件、设备报文/资源上限、各模型的硬件与延迟、长任务停止行为、第一组生态控制器、具体厂商合作接口与正式套件BOM。它们需要技术验证和采购数据，不靠架构文档预设为事实。
