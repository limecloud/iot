# 自动化 DSL 与执行引擎

更新日期：2026-11-03。状态：DSL v1 设计基线。语言由平台定义，YAML 为编写格式，JSON 为机器表示，Rust 负责类型化 AST 与执行。

当前正式规则支持设备事件、数值属性阈值边沿或每周定时触发、有界属性比较/all/any条件，以及 `actions[]` 中严格二选一的 `set` 属性写入或 `invoke` 动作调用。每条规则1–16个操作，复用统一命令账本、执行路由、每设备FIFO和unknown恢复，不引入第二套执行器。机器格式见 [rule.schema.json](../contracts/rule.schema.json)，已实现的行为与边界见 [自动化合同](../contracts/rules.md)，实施证据见 [24](24-实施计划与进度.md)。以下时间窗口条件、cron/日期计划、延时、任务及通用编译政策仍是设计范围，不能据此提交当前规则。

当前动作示例：

```json
{"version":1,"id":"button-tv","trigger":{"device":"device-button","event":"button.pressed"},"conditions":[],"actions":[{"device":"device-lamp","invoke":{"path":"remote.press","input":{"key":"home"}}}],"cooldown_ms":10000}
```

此例需要目标绑定实际支持 `remote.press` 的模型。`input` 映射为命令 `operation.value`，不是动态代码或任意工具名。预演不发送命令，启用后收到有效新事件才受理操作；同设备按序分发，不承诺跨设备事务或等待前一步成功后继续。已有模型换绑也核对 invoke 输入兼容。旧set规则格式和摘要保持兼容；含invoke快照不支持旧二进制降级读取。

家庭网页、SwiftUI和Compose支持单动作规则创建、编辑和完整操作展示；多操作规则使用TUI或CLI/API编辑，页面不会只保留首步覆盖。TUI同时支持事件和属性阈值来源，保留完整操作与毫秒冷却，预演为simulation.tui示例采样。AI草案本阶段继续只生成属性联动，当前真实模型的意图质量状态不因DSL扩展而提升。

属性触发使用`trigger.property`显式指定路径、模型单位、上升/下降、阈值和滞回，例见[环境到灯光](../contracts/examples/environment-light.json)。只有当前会话的新鲜confirmed采样参与；缓存保留原时刻，首次、重连、间断或重启只建立基线。滞回重新武装后，每次严格越界最多生成一次运行，冷却中的边沿不补发。网关v10耐久保存运行与采样证据，边沿基线不跨重启。CLI/API与TUI支持多步阈值规则，三端GUI提供单步表单，原生库可预演；属性依赖图在校验/预演/部署及恢复时拒绝闭环，动作按目标设备的全部阈值来源保守连接。静态图范围见[合同](../contracts/rules.md#属性依赖环路)；去抖、物理/事件副作用循环分析及运行时因果深度仍未实现。

条件比较支持数值eq/ne/lt/lte/gt/gte，布尔与文本eq/ne，按模型单位显式输入；顶层AND，all/any组合最多4层/32节点。未知或过期不能通过ne变成满足。预演使用网关当前条件快照，实际运行保存原条件与观测；未满足记录rule_conditions_not_met，不占命令预算或冷却，也不补发。机器入口与恢复边界见[正式合同](../contracts/rules.md#条件判断)。Web与TUI共用条件输入和预演核对，SwiftUI/Compose源码接入各自原生条件编辑器；三端单步表单与TUI完整保留条件树、毫秒冷却并显示原证据。非空条件显式核对trigger_matched，当前条件未满足时仍可明确启用等待新触发；原生源码、宿主库和端上运行分别记录。

## 1. 语义范围

每周定时使用trigger.schedule，包含严格HH:MM、IANA时区与ISO星期，例见[每天关灯](../contracts/examples/bedtime-light.json)。夏令时缺失时刻跳过，重复时刻只取第一次；UTC高水位不随回拨后退，漏轮询超过5秒、重启与Broker重连均不补发。定时不建立伪触发设备或刷新目标在线状态。游标、原UTC/本地发生证据、运行与命令原子写入v11；基础路径仍写v10，读v1–11，使用v11后不降回v10。具体恢复与校验政策见[定时合同](../contracts/rules.md#每周定时)。

Web、SwiftUI/Compose源码提供单操作定时表单，TUI/CLI支持完整多步；均先向网关校验获取schedule_preview.scheduled_at，再提供精确发生时刻做零副作用预演，明确启用才调度。客户端只做输入校验，不自行计算夏令时或补做漏发计划。定时和原事件/阈值共用条件、预算、FIFO、授权及unknown账本，AI草案范围不扩展。

规则由版本、身份、触发、条件、动作、冷却和运行政策组成。适合确定性事件联动；机器人运动算法、生成式对话和品类专业业务属于应用或设备，不塞入规则解释器。

```yaml
version: 1
id: hallway-light
trigger:
  device: hallway-motion
  event: motion.detected
conditions:
  - device: hallway-lux
    property: illuminance.value
    operator: lt
    value: 30
    unit: lux
actions:
  - device: hallway-light
    set:
      path: light.power
      value: true
cooldown_ms: 10000
```

示例中的设备别名在部署时解析为稳定 ID 并冻结，运行期间不依赖可变昵称。

## 2. v1 语言

| 语法 | 范围 |
| --- | --- |
| 触发 | 当前事件、有效属性边沿、时间计划、显式调用 |
| 条件 | 类型一致的比较、all/any、有界时间窗口 |
| 动作 | property.set、获准动作、有限延时、受限任务调用 |
| 运行政策 | 超时、最大步骤、并发上限、冷却、错误处理与恢复 |

只允许注册动作和稳定引用，禁止任意 Shell、动态代码、无限循环、任意网络地址和未登记工具。操作符和类型不做隐式字符串转数字。未知与 stale 值默认不满足依赖新鲜观测的条件。

## 3. 编译与部署

解析 YAML/JSON → Schema 校验 → 设备和模型引用解析 → 类型与单位检查 → 当前权限及风险评估 → 循环/资源检查 → 生成不可变 AST 与摘要 → 模拟 → 部署。

规则定义版本与部署修订分开。修改、启停和回滚均重验当前权；回滚创建新的部署记录，不改写旧执行。模拟默认不访问真实设备，输出会产生的命令及原因，不宣称当前硬件一定能执行。

## 4. 触发和时间

阈值规则定义边沿、去抖、滞回和冷却；避免每条温度上报重复开关。事件去重键为规则版本与原事件身份。历史补传默认不触发实时动作，确有回补需要的规则显式声明上限和政策。

时间计划包含时区与夏令时政策。重启后过期计划默认跳过，不补发旧控制；允许恢复的延时使用持久任务，恢复前再验期限、权和能力。墙上时钟用于计划，单调时钟用于单次执行超时。

## 5. 执行与恢复

规则运行创建 run_id，每步命令使用可追踪身份关联原触发。顺序动作逐步提交，不承诺跨设备原子；部分完成、明确失败、取消和未知分别记录。

失败处理为停止、继续允许的独立步骤或执行明确声明的补偿。补偿是新的真实副作用，需权限和幂等语义；不能将“关灯”自动视为“开灯”的无损回滚。

当前执行预算为每空间滚动60秒最多受理64条自动化命令，来自原命令账本，事件/阈值及全部规则共享；整条规则名额不足时保存拒绝运行，不受理步骤、不补发，重启与换名不清零。确切窗口、时钟及恢复边界见[正式合同](../contracts/rules.md#自动化执行预算)。同规则拒绝并发、有限排队或替换未开始的运行，以及因果链、最大触发深度与时间预算仍属于后续设计，总量限制不能替代因果追踪。

## 6. AI 协作

Agent 按模型和规则 Schema 生成草案，调用 validate/simulate 获取结构化错误与差异，再按精确部署合同执行。模型文本没有部署权。部署后的确定性执行不调用模型；需要生成式能力的场景通过有预算的应用任务显式组合。

## 7. 验收

使用虚拟时钟与事件向量验证：非法引用、类型/单位错误、stale、去抖、滞回、重复与历史事件、夏令时、重启延时、部分执行、未知回执、权限撤销、循环和预算。实机验收再验证真实传感器到执行器的完整路径。
