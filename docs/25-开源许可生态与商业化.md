# 开源许可、生态与商业化

更新日期：2026-11-01。项目采用 [Apache-2.0](../LICENSE)。

## 1. 许可范围

仓库原创软件、文档和设计资料采用Apache-2.0；第三方文件、依赖、模型权重、数据、声音、角色内容、字体及硬件资料按各自声明处理。文件或制品需其他许可时明确标注并加入发布清单，不能用根许可证覆盖他人作品。

Apache-2.0允许商业使用、修改和分发，并规定贡献者专利授权和相关终止条件。分发保留许可证、适用归属与NOTICE，修改按要求标注；不自动授予第三方商标、内容或认证资格。

## 2. 外部依赖治理

| 类别 | 要求 |
| --- | --- |
| 系统与标准栈 | 固定版本、源码/二进制来源、许可证、已知漏洞与替换边界 |
| GPL/AGPL等组件 | 按具体链接、修改与分发方式履行义务，不能仅靠适配器判断 |
| 模型权重与提供方 | 记录权重许可、商业/场景限制、API条款与数据政策 |
| 图像/语音/角色 | 内容权利、使用范围、生成来源与发布者责任 |
| 硬件及认证 | 板卡文件声明、供应商材料、型号认证和标识使用资格 |

当前来源观察：Home Assistant主仓Apache-2.0；ESPHome的Python等部分MIT、C++运行时GPLv3；zigbee2mqtt和zigpy有GPL义务；OpenRemote有AGPL义务。ThingsBoard当前主线对4.4.0+采用BSL条件，版本与具体条款以固定发行物为准。完整来源见 [02](02-参考项目与技术调研.md)。

适配器提供技术隔离，不改变这些许可。原创实现、合规复用和独立可选组件在制品清单中说明。公开发布前生成SBOM和依赖/归属清单，不把协议学习样本里的私有数据一起分发。

## 3. 生态贡献

贡献重点为板卡/BSP、驱动、物模型、协议/生态适配、组合包、内容、夹具、工具和场景应用。提交带来源、权利声明、型号限制、验证与维护信息。社区审核优先检查能力准确、当前授权、失败恢复和可复现证据。

初期采用仓库审核与明确发布者，不预建开放插件市场。第三方分发成熟后再完善发布者验证、包签名、撤回、恶意包响应和兼容治理；安装仍不等于业务授权。

## 4. 商业交付

| 交付物 | 客户价值 | 主要成本 |
| --- | --- | --- |
| 开发套件 | 板卡、工具、样例和完整AI开发路径 | 采购、资料、实验与维护 |
| 场景设备套件 | 固定BOM和验证体验 | 制造、认证、质检、物流与售后 |
| 能力/内容组合包 | 玩具、教育、陪伴等差异化体验 | 研发、内容权利、模型与运维 |
| 适配/定制服务 | 指定型号或生态的工程交付 | 实验、开发、资格与长期维护 |
| 部署与技术服务 | 安装、升级、诊断与恢复 | 人工、备件、服务范围与SLA |
| 可选云与模型服务 | 远程、托管、算力与内容 | 提供方、存储、流量、安全与支持 |

基础本地控制与已部署规则不因云订阅结束而失效。收费增值能力、离线范围、用量、数据位置、服务期限与售后责任应事先可理解；模型调用受理不等于计费结果已确定。

## 5. 商家与用户边界

商家可发布自有硬件、角色和组合体验，但不能默认读取用户空间、音视频或长期记忆。发布者权限、购买资格、包安装、数据授权和设备执行分别核验。

心理支持、教育、健身和机器人等专业应用由其运营方负责内容与服务质量、适用资质和产品要求。平台提供必要接口及政策能力，通用平台验收不替代这些专业门槛。

## 6. 套件交付门禁

型号/BOM稳定、身份注入、签名升级、故障恢复、许可、认证与适用声明、隐私政策、长稳、备件及售后范围齐备。开源下载、样机演示和某个模型成功对话都不能单独证明产品可交付。
